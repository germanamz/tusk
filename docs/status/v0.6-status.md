## Key Features in Detail

### Urgency Scoring Engine

Stateless `UrgencyEngine` in `internal/service/urgency.go`. Computes a weighted sum of 10 factors per task:

| Factor | Coefficient | Default Weight |
|--------|-------------|----------------|
| Priority | `priority / 4.0` | 6.0 |
| Due date | Sigmoid: `1 / (1 + e^(-0.5 * (14 - days_until_due)))` | 12.0 |
| Age | `min(days_since_creation / 365, 1.0)` | 2.0 |
| Active status | `1.0` if active | 4.0 |
| Blocking | `1.0` if blocks other tasks | 8.0 |
| Blocked | `1.0` if blocked by others | -5.0 |
| Tags | `min(tag_count / 3, 1.0)` | 1.0 |
| Project | `1.0` if has project | 1.0 |
| Annotations | `min(annotation_count / 2, 1.0)` | 1.0 |
| Waiting | `1.0` if wait_until in future | -3.0 |

Score = sum of (coefficient * weight) across all factors.

### Batch Data Loading

Scoring avoids N+1 queries via three new batch methods:

- `AnnotationRepository.CountByTasks` — `SELECT task_id, COUNT(*) ... GROUP BY task_id`
- `RelationRepository.CountBlockingByTasks` — blocking counts via `source_id` grouping
- `RelationRepository.CountBlockedByTasks` — blocked-by counts via `target_id` grouping

Tag counts derived from existing `TagRepository.GetTaskTagsBatch`.

### Per-Project Urgency Overrides

Projects can override individual urgency weights via config:

```toml
[projects.backend.settings.urgency]
blocking_weight = 15.0    # only override this one weight
# all other weights inherit from [urgency] globals
```

Sparse merge via pointer fields: `nil` = use global default, non-nil = override.

### `tusk next`

Returns the highest-urgency actionable task. "Actionable" means:
- Status is `pending` or `active` (non-terminal)
- `wait_until` is not in the future
- Not blocked by incomplete tasks

Returns error if no actionable tasks exist.

## Design Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Scoring location | In-memory in service layer | Sigmoid and conditional logic cleaner in Go than SQL; task counts typically <1000 |
| Urgency field | Non-persisted on `domain.Task` | Zero-valued by default, populated on read, avoids schema change |
| Batch loading | 3 bulk queries + in-memory scoring | Matches existing tag batch pattern; avoids N+1 |
| Sigmoid parameters | k=0.5, midpoint=14 days | Not configurable — internal tuning constants |
| Project overrides | Pointer fields for sparse merge | Users shouldn't repeat all 10 weights to tweak one |
| `tusk next` filter | pending + active | Both unstarted and in-progress work are actionable |
| Blocked check in Next | Per-task query in loop | Returns on first match, so typically 1 query |

### Known Limitations

- **No pagination** — `tusk list` returns all matching tasks
- **UDA values are untyped** — all values stored as strings; typed UDA validation deferred to v0.9
- **No UDA filter in MCP list** — MCP `tusk_task_list` uses explicit parameters, not filter syntax; UDA filter is CLI-only
- **Urgency sigmoid constants not configurable** — k and midpoint are internal; only weights are configurable
- **`tusk next` blocked check is per-task** — acceptable for typical task counts, could be batched if needed
