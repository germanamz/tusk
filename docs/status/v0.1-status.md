```
tusk add <title> [project:X] [priority:N] [due:DATE] [+tag...]

```

### Filter Syntax

TaskWarrior-inspired, parsed by a formal lexer/parser/resolver pipeline:

```
status:pending,active    # comma-separated OR
project:backend          # exact project name match
priority:2..4            # range (inclusive)
due:today                # relative date (today, tomorrow, thisweek)
due:2026-04-10..friday   # absolute/relative range
+api                     # include tag
-docs                    # exclude tag
parent:<short_id>        # direct children
```

Default list filter: `status:pending,active` (when no status specified).

## Architecture Summary

```
cmd/tusk/main.go          DI wiring, flag parsing, DB path resolution
internal/domain/           Pure data types, no dependencies
internal/repository/       Go interfaces only (no implementations)
internal/service/          Business logic, depends on repository interfaces
internal/sqlite/           SQLite implementations of repository interfaces
internal/filter/           Filter parser pipeline (lexer -> parser -> resolver)
internal/tui/              Cobra CLI commands + output rendering
migrations/                Embedded SQL migrations
tests/e2e/                 Black-box CLI tests
```

Dependencies flow downward only. Services never import `sqlite/`. The `tui/` layer calls services, never repos directly.

## Key Implementation Decisions

These decisions emerged during v0.1 implementation and supplement the design decisions in `tusk.md`:

### Double-pointer pattern for nullable updates

`TaskUpdate` uses `**string` (pointer-to-pointer) for nullable fields to distinguish three states: don't change (`nil`), set to null (`*nil`), set to value (`**"foo"`). This avoids a separate "fields to clear" parameter.

### Short ID collision handling

UUIDs are truncated to 8 hex chars for CLI use. On collision (checked at creation time via `repo.GetByShortID`), the ID is extended to 9+ chars. With ~16M unique values at 8 chars, collisions are rare but handled.

### Version auto-fetch in CLI

Users never pass version numbers. The CLI reads the task, extracts the current version, then sends the mutation. This adds one read per write but eliminates a major UX friction point. MCP callers will pass versions explicitly.

### Filter parser is a 3-stage pipeline

1. **Lexer** (`Lex`) — tokenizes into `TokenField`, `TokenTagInclude`, `TokenTagExclude`, `TokenText`
2. **Parser** (`Parse`) — builds AST (`FilterSet`), collects all errors (no short-circuit)
3. **Resolver** (`Resolve`) — converts AST to `domain.TaskFilter`, does repo lookups (project name -> UUID)

This separation allows future extension to boolean operators (OR/AND/NOT) by upgrading the parser without touching the lexer or resolver.

### Soft delete via status transition

`tusk delete` transitions to `status:deleted` rather than removing the row. Tasks remain in the DB for audit trails. The default list filter excludes deleted tasks.

### E2E test matrix

Every scenario runs 4 times: 2 DB modes (`--db` flag vs `TUSK_DB` env) x 2 output formats (text vs JSON). Catches environment and format-specific bugs.

### Known Limitations

- **No quoted string support in filters** — `title:"my task"` and `description:` filters are blocked until the lexer supports quoted strings
- **No boolean operators** — filters are AND-only; OR is only within comma-separated status values
- **No pagination** — `tusk list` returns all matching tasks
- **No sorting** — tasks returned in `created_at` order (urgency sorting is v0.4)
- **No config file loading** — `config/default.toml` exists as a template but isn't read at runtime
- **No `start` command** — the `start` transition shortcut (`pending -> active`) works but isn't exposed as the standalone `tusk start` in v0.1 *(correction: it IS implemented)*

## Build & Run

```bash
# Requirements: Go 1.26.1+, CGO_ENABLED=1

make build          # -> bin/tusk
make test           # unit + e2e
make test-race      # with race detector
make test-e2e       # e2e only
make vet            # go vet
make lint           # golangci-lint
make install        # -> $GOPATH/bin/tusk
```

DB location: `--db <path>` flag > `TUSK_DB` env > `~/.local/share/tusk/tusk.db`
