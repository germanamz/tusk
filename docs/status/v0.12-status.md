## What Was Built

v0.12 introduces **trailing window notes** — a persistent, append-only notebook scoped by project and player. Each note is a blob of markdown body plus free-form metadata, optionally attached to a task. Notes are immutable after creation; they can be archived but never edited. Listing applies a trailing window so agents and humans always see the most recent N entries without paging through history.

The window size flows through a four-tier resolution chain (CLI override → player DB setting → project settings → global config → hardcoded default of 20), letting an orchestrator trim individual players down to short-term memory while keeping the project-wide default intact. Notes ride the same `key=value` conventions the v0.11 CLI locked in — metadata namespaces under `meta.` (symmetric with task `uda.`), bodies accept `@file` / `@-` expansion, project scoping uses `project=<name>`.

Alongside notes, v0.12 ships an **MCP field-restriction layer**: a new `[mcp.blocked_fields]` config section maps tool names to lists of input fields an agent may not supply. Restrictions are validated at startup against a hand-maintained tool-field registry (unknown tools and unknown fields fail the config) and enforced at runtime before every mutating handler calls the service layer. Defaults lock down `tusk_project_modify.workflow` and `tusk_project_delete.force` so agents cannot reshape workspaces even with workflow/project write tools enabled.

A new top-level `tusk player modify` command lets operators set or clear the per-player `note-window-size` override from the CLI, and the player info view surfaces the override when set.

## Key Features in Detail

### Trailing Window Resolution

`NoteService.resolveWindowSize` walks four tiers in order: CLI override (`--window N` / MCP `window`), player DB setting (`players.note_window_size`), project settings (`ProjectSettings.NoteWindowSize` stored on the DB row, not the config file — projects moved to DB in v0.10), global config (`[notes].window_size`), hardcoded fallback (20). Lookup errors at any tier cause fallthrough rather than failure, so a missing player row or transient project fetch error silently drops to the next tier. Only positive values are honored; zero or negative at any tier is skipped.

The limit is applied at the SQL layer via `LIMIT` in the generated query, not post-fetch. That keeps large note histories from being materialized in Go just to slice them down.

### Note Prefix Resolution

Archive accepts either a full UUID or an 8+ character UUID prefix. The CLI calls `NoteService.FindByIDPrefix`, which delegates to `NoteRepo.FindByIDPrefix` — a `GLOB 'prefix*' LIMIT 2` query that is either unambiguous (one match), empty (no match), or reports ambiguity with both candidate IDs for the caller to disambiguate. The MCP `tusk_note_archive` tool deliberately requires a full UUID — agents already have the ID from `tusk_note_list` output, so prefix handling is a CLI convenience only.

### `--since` Duration Parsing

The note `--since` flag and the `tusk_note_list` MCP `since` parameter take different shapes: CLI accepts relative durations (`7d`, `24h`, `30m`), MCP accepts an RFC 3339 timestamp. The CLI path parses through a new `filter.ParseRelativeDuration` helper that extends Go's `time.ParseDuration` with `d` (24 h) and `w` (7 d) units. Compound forms like `1w2d` are rejected to keep the grammar unambiguous; zero or negative durations are rejected.

### MCP Field Restrictions

Field restrictions are a two-phase guard. At startup, `validateConfig` walks every `BlockedFields` entry and checks it against `toolFields`, a hand-maintained `map[string]map[string]struct{}` enumerating every declared input for every write tool. Unknown tool names, unknown fields, and dotted sub-keys all fail the boot. The registry lives next to `registerTools` in `server.go` so adding, renaming, or removing a parameter requires a matching registry edit — the startup check then catches any stale `blocked_fields` config.

At runtime, every mutating handler calls `s.checkBlocked(toolName, request)` before any service logic. A field is "supplied" when it is present in the request arguments map with a non-nil value — an absent key or explicit `null` passes through. When one or more blocked fields are present, the handler returns a tool-result error listing the offending fields in sorted order along with the tool name; the error mentions `mcp.blocked_fields.<tool>` so operators can trace the message back to the config surface.

The default policy ships two entries: `tusk_project_modify.workflow` (prevents agents from swapping a project's workflow, which is essentially re-scoping the whole workspace) and `tusk_project_delete.force` (prevents agents from bypassing the "has tasks" guard). Those tools remain in `disabled_tools` by default too; `blocked_fields` is the finer-grained knob for operators who opt them back in.

### `tusk player modify`

The new `tusk player modify <id> note-window-size=<N>` command rides the existing inline field lexer — the same grammar that drives task create/modify. `note-window-size=` with an empty value clears the override back to `NULL`, letting the project/global defaults take over. The modify command lives in `buildPlayerCmd` next to `tusk player register`; both are grouped under the `tusk player` parent that was already established pre-v0.11.

## Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Notes are append-only | Archive, never edit | Notebook semantics: the record of what an agent thought at a point in time should not mutate |
| `archived_at` nullable column | Soft-delete style | Matches task soft-delete; `NULL` means active, non-NULL means archived |
| Window applied in SQL | `LIMIT N` in generated query | Avoids materializing large histories in Go just to slice |
| Per-project override on the DB row | `ProjectSettings.NoteWindowSize` JSON field | Projects moved to DB in v0.10 — the config file no longer owns project metadata |
| Resolution fallthrough on lookup error | Silent skip to next tier | A transient player fetch error should degrade to the project/global default, not fail the list call |
| `meta.key=value` symmetric with `uda.key=value` | Prefix namespace on bare tokens | Consistent with v0.11 principle; bare unknown fields are rejected |
| Glamour for body rendering | CLI text mode only | Markdown bodies read like a notebook; JSON output stays raw so consumers aren't ANSI-polluted |
| CLI accepts prefix, MCP requires full UUID | Asymmetric by design | Agents already have the UUID from list results; humans need shorthand |
| `--since` units include `d` and `w` | Extend `time.ParseDuration` | Days and weeks are the ergonomic unit for note retention; compound forms rejected for clarity |
| Hand-maintained tool-field registry | `toolFields` map in `field_registry.go` | Reflection over MCP tool schemas is brittle; the registry is cheap, explicit, and startup-checked |
| Startup validation against registry | Reject unknown tools and fields | Blocked-field config drift should fail boot loudly, not silently allow writes |
| Dotted sub-keys rejected at startup | `uda.env` produces a validation error | Field-path semantics deferred; flat field names only in v0.12 |
| Runtime guard at the top of every handler | `s.checkBlocked(...)` returns before service calls | Defense in depth: config drift, race on reload, and arg-shape bugs all surface as the same tool error |
| Error message lists fields sorted | `[due, priority, title]` | Deterministic output for tests and for agents parsing the message |
| Default blocklist on project tools | `workflow` on modify, `force` on delete | The two fields an agent could use to reshape the workspace regardless of the top-level disable |

### Known Limitations

- Note bodies are stored verbatim with no size cap of their own; the 1 MB `[inline].max_expansion_size` only bounds `@file` / `@-` substitutions, not literal body arguments.
- `tusk_note_archive` requires a full UUID — the MCP surface does not accept 8-char prefixes the way the CLI does.
- `blocked_fields` only supports flat field names; dotted sub-keys like `uda.env` are rejected at startup and will need a field-path grammar in a later milestone.
- The trailing window is time-agnostic beyond `--since` — there is no "expire notes older than N days" retention sweep.
- Archived notes stay in the notes table forever; there is no prune command.
