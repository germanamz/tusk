# v0.11 Status

## Initiative: tusk task Subcommand Group

Every task-scoped verb now lives under `tusk task`. The flat, top-level verbs
are retired — their names are still reserved as hidden stubs that emit a hint
pointing at the new invocation, so typing `tusk add …` or `tusk link …` prints
a targeted error rather than crashing or silently doing nothing.

### CLI surface

Sixteen verbs moved under `tusk task`:

`create`, `list`, `get`, `modify`, `tree`, `start`, `done`, `delete`, `next`,
`annotate`, `claim`, `release`, `available`, `pop`, `link`, `unlink`.

Function renames inside `internal/tui`: `runAdd` → `runCreate`, `runInfo` →
`runGet`. These line up with the new subcommand names.

### MCP surface

Two tool renames (breaking):

- `tusk_relation_add` → `tusk_task_link`
- `tusk_relation_remove` → `tusk_task_unlink`

One visibility-group rename (breaking):

- `"relation"` → `"task_relations"`

Request and response shapes are unchanged. Clients still calling the old tool
names receive the server's standard "unknown tool" error — there is no
backward-compat alias.

### Config migration

MCP configs declaring `disabled_tool_groups = ["relation"]` must be updated to
`disabled_tool_groups = ["task_relations"]`. This is a breaking change.

### Shell completions

Consumers should regenerate shell completions after upgrade so the `tusk task`
subcommand tree is reflected in tab completion.
