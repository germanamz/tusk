## What Was Built

v0.11 regroups the CLI under explicit subcommand namespaces so the surface scales cleanly as the system grows. Every task-scoped verb moved under `tusk task`, old flat commands were removed with targeted "did you mean" errors, and MCP relation tools were renamed in lockstep (`tusk_task_link` / `tusk_task_unlink`).

Alongside the regrouping, v0.11 locks in a principle the CLI had been drifting toward since v0.9: entity properties flow through the inline `key=value` lexer, not ad-hoc Cobra flags. The two remaining flag-based entity properties — `--description` and `--uda` — were eliminated. `description=` and `title=` now flow through inline syntax with word-boundary `@file` / `@-` expansion for loading content from files or stdin. `uda.key=value` inline syntax replaces the `--uda` flag, matching the filter syntax that already existed.

A `tusk completion` subcommand was added so every future CLI change has a single regeneration command. Rich `Long` and `Example` help text was added to all task, project, and workflow commands. All documentation and E2E tests were rewritten to match the new surface.

## Key Features in Detail

### Command Grouping

The flat command surface (`tusk add`, `tusk list`, `tusk start`, etc.) was replaced by a single `tusk task` parent with 16 subcommands. The grouping was designed to scale: `tusk project`, `tusk workflow`, `tusk tag`, `tusk player`, `tusk config` already had their own namespaces; only task verbs were flat. Workspace-wide operations (`tusk undo`, `tusk export`, `tusk dashboard`) stay at the top level by design — they don't belong to any single entity.

Old flat commands are registered as hidden Cobra commands (`moved.go`) with `DisableFlagParsing: true`. They return a targeted error: `unknown command "add"; did you mean 'tusk task create'?`. This approach gives exact-match suggestions for known moved verbs while letting Cobra's built-in fuzzy matcher handle typos on the new names.

### Inline `@` Reference Expansion

The `@file` expander (`expand.go`) is a consumer-layer text pass — no lexer or AST changes. It runs on the final decoded string after the v0.9 lexer has collapsed quotes. This was a deliberate choice: the mid-string case (`description="see @./notes.md for details"`) cannot be represented as a stripped prefix marker in the AST, so the expander operates post-lexer.

Word-boundary semantics ensure `foo@bar.com` and `user@host` are never expanded. `@@` escapes to a literal `@`. `@-` reads stdin exactly once per invocation, enforced via a shared `expandState` struct across multiple field expansions in the same command. Binary files are rejected via a NUL-byte scan on the first 8 KB (git's approach).

### UDA Inline Syntax

The `uda.key=value` inline syntax unifies create, modify, and filter surfaces — `uda.env=prod` works identically on `tusk task create`, `tusk task modify`, and `tusk task list`. The `collectUDAs` helper walks the parsed field list and extracts dotted keys. Unknown bare fields (`env=prod`) are rejected with a "did you mean `uda.env`?" hint, so typos on UDA keys surface loudly instead of silently becoming UDAs.

## Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| No backward-compat aliases | Hidden stubs with "did you mean" errors | Pre-release; clean break avoids alias maintenance |
| `@` expansion at consumer layer | No lexer/AST changes | Mid-string `@` cannot be a prefix marker; pure text pass is simpler |
| `@@` escape convention | Not `\@` | Shell-friendly; matches `$$` in Make, `%%` in batch |
| Stdin once per invocation | `expandState` struct | Prevents confusion when both `title=@-` and `description=@-` appear |
| Unknown bare fields rejected | "did you mean uda.X?" hint | Catches the common typo where user forgets the `uda.` prefix |
| MCP tools renamed in lockstep | `tusk_task_link` / `tusk_task_unlink` | CLI and MCP share the same mental model |
| Cobra flags only for invocation concerns | `--player`, `--format`, `--all`, etc. | One way to set entity fields (inline); flags for everything else |

### Known Limitations

- `tusk undo` is not yet implemented — the placeholder in the roadmap targets v0.14 with the event log
- Shell completion scripts must be regenerated manually after upgrades; there is no auto-install mechanism
- The `@` expander does not re-scan substituted content for nested references — expansion is one level deep by design
