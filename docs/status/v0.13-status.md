## ROADMAP.md Migration — markdown rendering complete

`tusk task tree project=<name> --format markdown` now emits a complete markdown document that mirrors the legacy hand-maintained `ROADMAP.md`: an H1 heading using the title-cased project name, a `> ` blockquote for the project description (Phase 1–2), nested H2/H3/bullet structure for the task tree (Phases 3–4), inline tokens for non-binary metadata (`status=`, `level=`, `priority=`, `due=`, `order=`, `uda.*=`, `+tag`), and labeled `**Annotations:**` / `**Notes:**` sub-blocks per task plus a project-scoped notes block under the H1 (Phase 5).

Annotations and notes render in chronological order (`created_at` ascending). Per-task notes carry `(player_id[, key=value…])` parentheses with alphabetically-sorted metadata; values containing whitespace or registered prefix characters are quoted by the same `quoteUDAValue` helper used for inline UDAs. Multi-line note bodies put the first line inline after the colon and indent subsequent lines under the bullet text. Heading-rendered tasks emit the labels at column 0; bullet-rendered tasks emit them as sub-bullets one indent level deeper than the bullet itself. Archived notes never reach the renderer (the gathering layer queries with `IncludeArchived: false`). Project-level notes (`task_id IS NULL`) appear under the H1 description before the first task.

The renderer rejects `--rollup` and multi-project trees; an empty workspace emits no output. No new dependencies, no schema migrations, no public API additions beyond the renderer surface.
