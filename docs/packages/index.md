# internal/index

SQLite-backed index. Owns the schema (nodes, edges, path_refs, embeddings, node_embeddings, embed_queue, file_state, skipped_files, workflow_drift, property_drift, meta) and the per-table repos. Sub-unit `nodes` rows carry a structural-address id (`<fileID>#S1.2P3`) and a `content_hash`; vectors are content-addressed — `embeddings` is keyed by `(content_hash, model)` and `node_embeddings` maps each node-chunk to its shared vector. Opens the DB in WAL mode with `busy_timeout=5000` so reindex, watcher, and MCP tool calls can share the file safely.

`embed_queue` holds embed jobs (keyed by node id) and reindex jobs (keyed by `reindex:<path>`). An embed job that failed `MaxEmbedAttempts` times is parked: `parked_at` is set, `DrainEmbed` skips it, and `Depth`, `DepthByKind` and `ListNodeIDs` leave it out; `CountParked` and `ListParked` report it. `Enqueue`, `EnqueueMany` and `EnqueueAllEmbeddable` re-arm a parked job. The `nodes_drop_embed_job` trigger deletes a node's embed job whenever the node row is deleted, whatever deletes it; `DeleteOrphans` sweeps jobs an index written before the trigger leaked (#845).

## Public surface

- `Open(path string) (*Store, error)` — opens or creates the DB and switches it to WAL. On a new file that switch is a write, and when two processes switch the same new file at once SQLite fails the loser straight away with `SQLITE_BUSY` instead of waiting out the busy timeout, so `Open` retries it for up to the same 5 s (#839).
- `RemoveArtifacts(dbPath string) ([]string, error)` — deletes the DB file together with its `-wal`/`-shm` sidecars (absent files are not an error); returns the paths removed. `OpenOrRebuild`'s schema-mismatch rebuild and `Recreate` use it to clear a stale temp DB rather than orphaning sidecars.
- `SwapInPlace(srcDB, dstDB string) ([]string, error)` — renames a checkpointed, closed DB over `dstDB` after dropping `dstDB`'s `-wal`/`-shm`; returns the `dstDB` artifacts it replaced. The rename replaces the file in one step, so `dstDB` is never missing.
- `Recreate(dbPath string) ([]string, error)` — what `internal/reset` runs: bootstraps an empty DB at `dbPath + ".reset"` and copies it into `dbPath` with SQLite's online backup, as one write transaction. The file and its `-wal`/`-shm` stay put, so another tusk process reading the index during a reset reads the old index or the empty one (#839). Replacing the file by name can't promise that: SQLite opens the sidecars by path after the main file, so a process opening the index mid-swap can pair the old file with the new sidecars and read a malformed image. When the copy fails (a file too corrupt to open, or a lock held past the busy timeout), `Recreate` falls back to `SwapInPlace`, so reset still clears a wedged index.
- `NodeRepo`, `EdgeRepo`, `EmbeddingRepo`, `EmbedQueueRepo`, `FileStateRepo`, `DriftLog`, `PropertyDrift`, `MetaRepo` — narrow CRUD facades.
- `FileStateRepo.RecordSkip` / `ClearSkip` / `ListSkips` — the `skipped_files` table: one row per file reindex acked without indexing because of a fault, with the error text. The methods live on `FileStateRepo` because the table is path-keyed and follows the file lifecycle, and `FileStates` is already wired into every reindex config.
- `EdgeRepo.ListBySourcePath` — every edge a file declares, its own and its sub-units', in one query. The sub-unit sync diffs it against each unit's derived edges.
- `EdgeRepo.ListBySourceFile(fileID)` — the edges of a file and of each of its sub-units, by the id range `SubUnitIDRange` gives (a BINARY range, not GLOB, so `[` and `_` in an id match literally). `EdgeListRun` reads it when `EdgeListRequest.FromSubUnits` is set, so `query.EdgeListRun` can fold a file's sub-unit copies of a link onto the file's row (#848).
- `EdgeListRun(repo, EdgeListRequest)` — the raw `edge list` lookup by `From`, `To`, `Type` or `TypeRef`, rows as stored. The verb the CLI, MCP and aliases call is `query.EdgeListRun`, which folds them and, given the manifest's `EdgeTypes`, reads an inverse label as its edge type with `From` and `To` swapped and reports an undeclared type that lists nothing (#850).
- `EdgeRepo.ReplacePathRefs` / `PathRefsFrom` / `PathRefsTo` / `AllPathRefs` — the `path_refs` table: one row per (page, paths edge type, path, line), keyed to the page's node row with `ON DELETE CASCADE`. The methods live on `EdgeRepo` because a path ref is an edge whose target is a path, and every pipeline that rewrites a page's edges already holds that handle.
- `SectionSpans(*sql.DB, fileID)` / `InnermostSection(spans, line)` — a file's numbered section rows, and the deepest one holding a line. `tusk query --include paths`, `tusk doctor` and `tusk claude refs` use them to name the section a path mention sits in.
- `RefLookup` semantics live in `internal/node` but bind to `*NodeRepo` in production via `node.NewIndexRefLookup`.
- `NodeRepo.LinkNames(linkCase)` / `NodeRepo.FileNames(linkCase)` — the two ways to resolve a wikilink that names a file by name (#791). `LinkNames` loads every file row into a `wikilink.Names` for a pass over the whole vault; `FileNames` answers one name at a time through the `nodes.name_key` column, for paths that resolve a handful of links (one note's refs, one page in the reader). `FileNames` is also a `wikilink.Lookup`: its `Exists`, `Sections` and `Blocks` answer what a `#fragment` can name in a file (#808, #819).
- `EdgeRepo.ResolveLinks(names)` and the `ResolveLinks(nodes, edges, linkCase)` wrapper — point every looked-up edge (`edges.link IS NOT NULL`) at the node its link text names now (`wikilink.ResolveTarget`): the file a name or path names, then the section a heading fragment names in it or the unit a block reference's `^id` names, or back at the text when the file is missing or a name matches several. Writers store such a link with its text as the target and leave the lookup to this pass, so a vault indexed in any order converges, and a file added, removed or renamed, or a heading renamed or moved, changes what a link finds without any linking file being re-parsed. A pass reads each target file's sections and block ids once. A re-pointed edge that duplicates one its source already has is deleted, keeping the path-written edge over a name-form twin. A fallback row (a fragment that named nothing, left on its file) is never deleted and never deletes another, because a later pass may find its heading or block; when its source links the file already, it parks at the file id plus the fragment (dangling) instead of doubling the edge, and doctor reports it as `missing-heading` or `missing-block`.
- `EdgeRepo.RenameLink(sourcePath, oldName, newName)` — rewrite the link text of a file's name-form rows after `tusk node move` changed `[[oldName]]` to `[[newName]]`, sub-units' rows included. A full id as the new text makes a plain edge, unless the link carries a fragment, which keeps it looked up.
- `EdgeRepo.RetargetEdges(oldID, newID)` — the move fix-up for incoming rows: every edge pointing at `oldID` or a sub-unit under it is re-pointed at `newID`. A path-written heading link's text (`[[notes/old#Setup]]`) moves with it, so the next lookup reads the new id.

## Notes

The package registers a deterministic `regexp(pattern, value)` SQL function at init, so every connection the `sqlite` driver opens has it. SQLite reserves the `X REGEXP Y` operator but ships no implementation, and calls this function for it. It backs the filter's `path`/`id` glob patterns (see [`internal/pathglob`](pathglob.md)). The implementation is Go's RE2, which runs in linear time, behind a small bounded cache of compiled patterns that is safe to share across connections. A NULL argument yields NULL, and a pattern that doesn't compile is an SQL error.

WAL + busy_timeout means the watcher can write while a long-running `tusk_query` reads — but reindex's own ordering is what gates correctness, not the DB. See `internal/reindex` for the cross-pass resolution issue.

`Open` applies a small set of idempotent migrations after the bootstrap schema — dropping the dead `manifest_snapshot`/`warnings` tables, the unused `idx_file_state_lease` index and the edges indexes #838 retired (`edges_source_idx`, `edges_type_idx`, `edges_kind_idx`), and adding the nullable `nodes.start_line` / `nodes.end_line` columns (a sub-unit's file line range) and the `nodes.name_key` / `edges.link` columns (a file's folded name, later also a section's heading key and a block's `^id` key, and an edge's looked-up link text, #791, #808 and #819) to indexes that predate them. `name_key` is backfilled from each file's path on that first open; section and block keys and `edges.link` fill in on the full pass the edge-derivation version bump forces. It also adds `edges.position` (#848), the 1-based place of a target among the targets of one type that its file writes, in the order written (a frontmatter list, then body links); `EdgeRow.Position` carries it, 0 standing for NULL, and every listing sorts a source's targets of one type by it. Sub-unit and structural edges leave it NULL. `ADD COLUMN` keeps every row and vector; the new columns stay NULL until reindex renumbers the rows (see `internal/reindex`). A new table added as `CREATE TABLE IF NOT EXISTS` (like `skipped_files` or `path_refs`) reaches existing indexes on their next `Open` with no `SchemaVersion` bump. Incompatible on-disk schemas are not migrated in place: `OpenOrRebuild` drops and rebuilds the DB from the authoritative `CREATE TABLE` DDL, keyed on `SchemaVersion`. `edges.position` is the order a file writes its targets in, not a sibling order: `tree=` / `parent=` results are still sorted by the source node's `OrderedBy` property at query time (see `internal/manifest`).

The index never runs `ANALYZE`, so the planner has no `sqlite_stat1` and can't tell a column with two or three values (`edges.type`, `edges.kind`, `nodes.kind`) from a selective one. It probed through such an index wherever a lookup named one beside a node id, and walked most of the table per probe: `ResolveLinks`' dedupe, a sub-unit sync's `DeleteBySourceAndType` and every filter arrow were quadratic in edges (#838). So no edges index leads with `type` or `kind` (a read by type alone, `ListByType`, scans); `edges_source_target_idx(source_id, target_id)` serves lookups by source and finds an edge's twin. Where another index could still win, the statement names its own: `ResolveLinks`' twin lookups and the filter compiler's edge predicates say `INDEXED BY`, since the `UNIQUE` index leads with `(source, type)` and stays, and the reads of one file's sections and block ids mark `kind` and `type` with a unary `+` so the id range drives them while `nodes_type_idx` keeps serving `type=` filters. `plan_test.go` pins those plans.
