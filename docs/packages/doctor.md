# internal/doctor

Reads workspace health from the index — skipped files, workflow drift, property drift, ref-resolution drift, dangling edges, named paths that are gone, edges their edge type forbids, undeclared types, manifest declaration errors, manifest rule violations, embed queue depth and retries, and the resolved graph-expansion config — and returns one report whose findings each carry a severity. Backs `tusk doctor`, the `tusk_doctor` MCP tool, and doctor aliases (`tusk run` / `tusk_run`).

## Public surface

- `Run(Config) (*Report, error)` — synchronous health check. `RunWithMigration(Request)` runs the migration pass first and is what every surface calls.
- `Migrate(Config) (MigrationReport, error)` — auto-migrates any legacy `__cli__` / `__mcp__` edge rows left over from pre-frontmatter `tusk edge add` / `tusk_edge_add` calls back into the source node's frontmatter. Runs by default ahead of `Run`; `tusk doctor --no-migrate` (and the equivalent MCP flag) skips it for a diagnostic-only pass. A row whose edge type is no longer declared in the manifest cannot be written to frontmatter, so it is reported as skipped and left in the index rather than aborting the whole report — doctor never dies on the drift it exists to diagnose.
- `CompileRules(*manifest.Manifest) ([]CompiledRule, []RuleError)` — validates every `[rule.<name>]` declaration and returns the runnable ones plus one `RuleError` per problem, both sorted by rule name. Pure, so `tusk reload` / `tusk_reload` call it too and list each `RuleError` under `warnings`. `Run` needs `Config.DB` to run the compiled rules; without it, rules are validated but not run.
- `CompileChecks(*manifest.Manifest) ([]CompiledCheck, []CheckError)` — validates every `[check.<name>]` declaration the same way: runnable checks plus one `CheckError` per problem, sorted by name.
- `CheckRunner` / `CheckResult` — the port `Run` calls a project check through (`Config.Checks`): a shell command, a working directory and a timeout in, the exit code, the output and whether it timed out back. `internal/checkexec` implements it. Nil (MCP, aliases, and the CLI without `--checks`) means checks are validated but not run, and `Report.ChecksSkipped` counts them.
- `ManifestWarnings(*manifest.Manifest) []string` — the manifest problems that don't fail a load, worded for reload: rule errors, check errors, then unknown keys. `tusk reload` and `tusk_reload` both list them under `warnings`.
- `Issue` shape — `Kind`, `Severity`, `NodeID`, `Message`, `Locations` (JSON `kind`, `severity`, `node_id`, `message`, `locations`). Every surface serializes it as is.
- `Report.Counts()` — per-severity totals (`Errors`, `Warnings`, `Advice`). The CLI summary line, its exit code, and the MCP `error_count` / `warning_count` / `advice_count` all come from it.
- `SeverityFor(kind)` — the classification, from one table (`severityByKind`):
  - `error` (the vault or the index is wrong): `dangling-edge`, `ambiguous-wikilink`, `edge-type-violation`, `edge-cardinality-violation`, `ref_dangling`, `ref_ambiguous`, `ref_type_mismatch`, `ref_cycle`, `required-missing`, `enum-violation`, `type-mismatch`, `workflow-violation`, `skipped-file`, `graph-expansion-invalid-edge`, `alias-invalid`, `context-invalid`, `context-pinned-missing`, `rule-invalid`, `check-invalid`.
  - `warning` (correct but degraded): `undeclared-property`, `undeclared-type`, `embed-retry`, `embed-failed`, `embed-no-chunks`, `embedding-drift`, `sub-units-disabled-dirty`, `legacy-cli-edge`, `legacy-mcp-edge`, `graph-expansion-unknown-edge`, `graph-expansion-no-edges`, `graph-expansion-weight-zero`, `path-missing`, `index-not-built`, `index-schema-stale`, `missing-heading`, `missing-block`, `manifest-unknown-key`, `rule-ignore-unused`.
  - `advice` (changes nothing about correctness): `embed-large-chunk`, `embedding-prefix-hint`.
  - A rule violation's kind is `rule:<name>` and a check finding's `check:<name>`; each carries its rule's or check's own severity, so neither is in the table. `edge-cycle` is in it as `error`, but every finding carries its edge type's `acyclic` level.

## Notes

- **One report, errors first.** Checks leave `Severity` empty (except rule violations, which carry their rule's); a final pass stamps the rest from the kind and stable-sorts the issues error, warning, advice, keeping check order within a severity. A test parses the package for every `Issue*` constant and fails if one has no severity. Manifest alias and `[context]` rejections and pins that no longer resolve are issues too (`alias-invalid`, `context-invalid`, `context-pinned-missing`), and `Migrate` reports each legacy row it leaves in place as a `legacy-cli-edge` / `legacy-mcp-edge` warning naming why (`MigrationReport.Unmigrated`); `MigrationReport.Migrated` stays a log of what moved.
- **Ambiguous names.** A dangling edge from a wikilink that names a file by name (`[[dup]]`, see [`internal/wikilink`](wikilink.md)) is reported as `ambiguous-wikilink` when two or more files have that name, with the files in the message, so the author can write the path of the one they meant. A name no file has stays a `dangling-edge` (#791).
- **Headings a link misses.** A wikilink whose `#fragment` names no heading or sub-unit of an existing note (`[[auth-rfc#Renamed]]`, see [`internal/wikilink`](wikilink.md)) resolved to the note itself, or parked at the note's id plus the fragment when its source links the note already (see `index.ResolveLinks`). Either way it is a `missing-heading` warning rather than a dangling edge, since the note is still linked; the message names the link and the note. A block reference (`#^id`) whose id no unit of the note carries is the same miss, reported as `missing-block` (#819). A note has sections for a heading link to find only while `section` is indexed, and a block id can sit on a unit of any other kind, so `missing-heading` is reported only while sections are indexed and `missing-block` only while every other kind is (`fragmentTargets`, #853). With `sub-units = false` neither is reported. A fragment link into a note that doesn't exist is still a `dangling-edge` (#808).
- **Sub-unit rows the setting leaves out.** `sub-units-disabled-dirty` is reported when the index holds sub-unit rows the manifest no longer indexes: any row with `sub-units = false`, or rows of the kinds a `sub-units` list leaves out, named with their counts (`list-item 1, table-cell 2`, #853). The next `tusk reindex` drops them, since a changed setting forces a full pass; doctor doesn't clean them itself.
- **One finding per dangling link.** A link in a paragraph is carried by the file row and every sub-unit above it, so dangling edges are grouped by (file id, edge type, target), and missing headings by (file id, edge type, target, link): `NodeID` is the file id and the sub-unit ids carrying the same link are `Locations`.
- **Named paths that are gone.** `path-missing` reads the `path_refs` table (edge types with `paths = true`; see [`internal/pathref`](pathref.md)) and checks each named path against the disk in `Config.Root`, matching each segment's case exactly so macOS and Linux agree. Only an anchored ref is checked, one whose first segment exists at the root, so a span that never named a path stays quiet. Links are refs too, so a broken relative link to a note or a file is reported here. One issue per (page, edge type, path): `NodeID` is the page, the message names the lines, and `Locations` lists the innermost sections holding them. It is a warning because a plan may name a file that isn't written yet; `--fail-on warning` makes it gate CI.
- **Edges their edge type forbids.** `tusk edge add` and node create/modify refuse an edge whose source or target type is outside its edge type's `from` / `to`, and `tusk edge add` refuses a second target on a one-to-one or many-to-one type. Reindex indexes a hand-edited file as written, so doctor checks the current edge table: `edge-type-violation` for a disallowed source type (once per source and edge type) or target type (once per edge), and `edge-cardinality-violation` for a source with more than one target on a single-target type. Reading the edge table rather than a reindex-time record catches a target that changed type after its source was indexed. Only `direct` edges are checked; derived edges belong to `ref_type_mismatch`, and a sub-unit's copy of a body link is covered by the file row's finding. Cardinality constrains the source side only, as `tusk edge add` does.
- **Index never built.** `index-not-built` fires when meta has no `index.LastReindexAtKey`, which only a completed reindex pass writes; node writes add rows without it. Every other check reads the index, so on a fresh checkout doctor would otherwise report a clean vault it never looked at (#787). It is a warning, since a new workspace isn't a broken one: `tusk doctor --reindex` runs the structural pass first (no embedder, at least one worker, under the workspace lock doctor already holds), and `--fail-on warning` turns a forgotten `--reindex` into a failure. Needs `Config.Meta`; skipped without it.
- **Index built under another schema.** `index-schema-stale` fires when the `index.ManifestSchemaKey` the last reindex recorded differs from `Config.Manifest.SchemaFingerprint()`: `tusk.toml`'s node, edge or behavior declarations were edited and no pass has applied them yet, or the index predates the key. Edges and drift are derived when a file is parsed, so until then the drift checks report against the old declarations (#831). A warning, since the next `tusk reindex` re-processes every file and clears it. An index no pass has built is `index-not-built`'s finding instead. Needs `Config.Meta` and `Config.Manifest`.
- **Skipped files.** `skipped-file` reads the `skipped_files` records reindex writes (see `internal/reindex`) through `Config.FileStates`. `NodeID` is the file path, since a file that never indexed has no node id. When the file's own node row is still indexed (it parsed once, then broke), the message says queries still serve that last good version.
- **Undeclared types.** `undeclared-type` reports one issue per node type used by indexed file rows but missing from the manifest, with the node ids as `Locations`; such nodes skip property validation entirely. It only runs when the manifest declares a node type of its own (the built-in sub-document types the loader merges in do not count), so a schemaless vault is not flagged.
- **Orphaned drift is never reported.** Workflow / property drift is only written while validating a live node, so a row whose node was deleted or renamed away is an orphan with no repair path. `Run` skips such rows at read time (a node-existence filter), and `reindex.Run` sweeps them from the drift tables (`DeleteOrphans`) so they do not accumulate. Together these stop doctor from pointing at ghost node ids forever.
- **Graph-expansion edge-types are validated with the query path's grammar** (`typeref.Parse`), so doctor agrees with what a real `--semantic` query does: a malformed entry (e.g. `Refs`) is flagged `graph-expansion-invalid-edge` (it hard-fails every semantic query), a well-formed scoped ref like `:references` whose type is declared is not flagged, and an undeclared-but-well-formed name stays `graph-expansion-unknown-edge` (the walker silently skips it). `enabled=true` with an empty `edge-types` list is a `graph-expansion-no-edges` no-op.
- **`embed-retry`** surfaces embed-queue rows that have failed at least once (`attempts > 0`) and are still being retried, with their attempt count and last error, so a failing embed is visible rather than hidden behind the queue-depth counter.
- **`embed-failed`** surfaces embed-queue rows that failed `embed.MaxEmbedAttempts` times on their own input and were parked (see [`internal/embed`](embed.md)): the node has no vector, so semantic search misses it. The message carries the last error and what re-arms the row (the node changing, `tusk reindex --force`, an `[embeddings]` change). A parked node is not also an `embed-no-chunks`. `Report.EmbedFailed` counts them apart from `EmbedQueueDepth`, which is pending rows only, and `Report.EmbedWaiting` says the pending rows wait for an `[embeddings]` section because none is configured; renderers label the depth line with it (#845).
- **Embedding settings.** `embedding-drift` compares stored vectors with the configured vector key (model plus `num-ctx`), and the `embed-large-chunk` and oversize sub-unit checks measure against the configured `chunk-max-bytes`. `embedding-prefix-hint` is advice: the model belongs to a family trained with instruction prefixes (`nomic-embed-text`, `embeddinggemma`, `mxbai-embed-large`, `snowflake-arctic-embed`, `snowflake-arctic-embed2`, matched on the last path segment of the model name) and a prefix it expects is unset: for a two-sided family (nomic, embeddinggemma) either prefix, so a config with only one side set is flagged with the missing one; for a query-only family the query prefix. A prefix set explicitly to `""` in `tusk.toml` counts as a deliberate opt-out and silences that side (`Manifest.EmbeddingsKeyDefined` tells it apart from an absent key). The message names the strings from the model card, says how to opt out, and suggests measuring, since the gain depends on the vault.
- **Manifest rules.** A `[rule.<name>]` is a convention written as a check that names the nodes breaking it. `rules.go` splits the work in two. The shared layer handles the name, `severity` (`error` unless set; `warning` and `advice` also allowed), `description`, unknown keys, the `rule-invalid` issue for a bad rule, and one `rule:<name>` issue per violation with the description as message. The kind layer is a registry (`ruleKinds`): each kind owns the manifest key that selects it, a declaration sets exactly one, and the kind compiles to a `ruleMatcher` that returns violations. Today the only kind is `filter`: its matches are the violations. Adding a kind means a field on `manifest.Rule`, a registry entry, and a matcher; a test checks every kind key is a decoded `manifest.Rule` field.
- **Filter rules.** The filter is parsed and validated with `internal/filter` when the rules compile, and compiled to SQL each time the rule runs. Validation is `filter.ValidateStrict` when the manifest declares node types (`DeclaresUserNodeTypes`), so a misspelled type, property, or enum value is a `rule-invalid` error instead of a rule that matches nothing forever; a schemaless vault gets the plain `filter.Validate` that `tusk query` uses. The SQL is compiled with `FilesOnly` unless the filter's outer level selects a built-in sub-unit type (`filter.OuterTypes`), because sub-units share their file's `path` and a path rule would otherwise report every section of a matching file. It is compiled with `Config.Now` as the clock, so a relative date (`today-90d`) or a `modified-since:` duration means the day doctor runs, even in a long-lived MCP server; the driving adapters set `Now`, and a rule that needs it fails the run when it is zero. Violations are sorted by node id.
- **Exceptions to a rule.** A node's `tusk-ignore` frontmatter (`manifest.RuleIgnoreKey`) names the rules it is an accepted exception to, as one name or a list (#852). `rule_ignore.go` reads every file node that sets it (`NodeRepo.ListFileNodesWithProperty`) and drops the matching violations; a sub-unit violation is covered by its file's value. An entry that exempts nothing is a `rule-ignore-unused` warning: it names a rule the manifest doesn't declare, the rule ran and the node no longer breaks it, or the value isn't a rule name or a list of them. An entry naming a rule that failed to compile is skipped, since `rule-invalid` already reports that rule.
- **Cycles.** `edge_cycle.go` reads each edge type whose `acyclic` level is not none (`checkEdgeCycles`), ref properties included, and finds the strongly connected components that hold a cycle (Tarjan, over sorted ids so the output is stable). One `edge-cycle` issue per component: `NodeID` is its first id, the message shows the shortest cycle from it (breadth-first), and `Locations` lists the members off that cycle. Direct and derived rows count; structural rows and the built-in sub-document types (when sub-units are on) are skipped, a sub-unit's copy of a body link is left to the file row, and a link to a heading counts as a link to its file. The severity is the edge type's level (#852).
- **Unknown manifest keys.** `manifest-unknown-key` reports each `manifest.UnknownKey` with the dotted key as `NodeID`: a typo inside a known table, or a table tusk doesn't read (#852). A warning, because the key does nothing and a newer tusk may read it.
- **Project checks.** `checks.go` runs each valid `[check.<name>]` in name order through `Config.Checks`, from `Config.Root`, with its `timeout-seconds` (`DefaultCheckTimeout`, 60s, when unset), after every other check. Exit 0 passes whatever it printed. A failing command's output lines shaped `path:line: message` (`path:line:col:` too; a path with no spaces or colons past a drive letter, so a timestamped log line isn't one) are one `check:<name>` finding each, with `path:line` as `NodeID`. A failing command that prints none is one finding quoting its last three output lines, and a timeout or a command that couldn't start is one finding saying so. Only the CLI wires a runner, under `--checks`, because the command is shell text from `tusk.toml` (#852).
