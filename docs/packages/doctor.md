# internal/doctor

Reads workspace health from the index — skipped files, workflow drift, property drift, ref-resolution drift, dangling edges, edges their edge type forbids, undeclared types, manifest declaration errors, embed queue depth and retries, and the resolved graph-expansion config — and returns one report whose findings each carry a severity. Backs `tusk doctor`, the `tusk_doctor` MCP tool, and doctor aliases (`tusk run` / `tusk_run`).

## Public surface

- `Run(Config) (*Report, error)` — synchronous health check. `RunWithMigration(Request)` runs the migration pass first and is what every surface calls.
- `Migrate(Config) (MigrationReport, error)` — auto-migrates any legacy `__cli__` / `__mcp__` edge rows left over from pre-frontmatter `tusk edge add` / `tusk_edge_add` calls back into the source node's frontmatter. Runs by default ahead of `Run`; `tusk doctor --no-migrate` (and the equivalent MCP flag) skips it for a diagnostic-only pass. A row whose edge type is no longer declared in the manifest cannot be written to frontmatter, so it is reported as skipped and left in the index rather than aborting the whole report — doctor never dies on the drift it exists to diagnose.
- `Issue` shape — `Kind`, `Severity`, `NodeID`, `Message`, `Locations` (JSON `kind`, `severity`, `node_id`, `message`, `locations`). Every surface serializes it as is.
- `Report.Counts()` — per-severity totals (`Errors`, `Warnings`, `Advice`). The CLI summary line, its exit code, and the MCP `error_count` / `warning_count` / `advice_count` all come from it.
- `SeverityFor(kind)` — the classification, from one table (`severityByKind`):
  - `error` (the vault or the index is wrong): `dangling-edge`, `edge-type-violation`, `edge-cardinality-violation`, `ref_dangling`, `ref_ambiguous`, `ref_type_mismatch`, `ref_cycle`, `required-missing`, `enum-violation`, `type-mismatch`, `workflow-violation`, `skipped-file`, `graph-expansion-invalid-edge`, `alias-invalid`, `context-invalid`, `context-pinned-missing`.
  - `warning` (correct but degraded): `undeclared-property`, `undeclared-type`, `embed-retry`, `embed-no-chunks`, `embedding-drift`, `sub-units-disabled-dirty`, `legacy-cli-edge`, `legacy-mcp-edge`, `graph-expansion-unknown-edge`, `graph-expansion-no-edges`, `graph-expansion-weight-zero`.
  - `advice` (changes nothing about correctness): `embed-large-chunk`, `embedding-prefix-hint`.

## Notes

- **One report, errors first.** Checks leave `Severity` empty; a final pass stamps it from the kind and stable-sorts the issues error, warning, advice, keeping check order within a severity. A test parses the package for every `Issue*` constant and fails if one has no severity. Manifest alias and `[context]` rejections and pins that no longer resolve are issues too (`alias-invalid`, `context-invalid`, `context-pinned-missing`), and `Migrate` reports each legacy row it leaves in place as a `legacy-cli-edge` / `legacy-mcp-edge` warning naming why (`MigrationReport.Unmigrated`); `MigrationReport.Migrated` stays a log of what moved.
- **One finding per dangling link.** A link in a paragraph is carried by the file row and every sub-unit above it, so dangling edges are grouped by (file id, edge type, target): `NodeID` is the file id and the sub-unit ids carrying the same link are `Locations`.
- **Edges their edge type forbids.** `tusk edge add` and node create/modify refuse an edge whose source or target type is outside its edge type's `from` / `to`, and `tusk edge add` refuses a second target on a one-to-one or many-to-one type. Reindex indexes a hand-edited file as written, so doctor checks the current edge table: `edge-type-violation` for a disallowed source type (once per source and edge type) or target type (once per edge), and `edge-cardinality-violation` for a source with more than one target on a single-target type. Reading the edge table rather than a reindex-time record catches a target that changed type after its source was indexed. Only `direct` edges are checked; derived edges belong to `ref_type_mismatch`, and a sub-unit's copy of a body link is covered by the file row's finding. Cardinality constrains the source side only, as `tusk edge add` does.
- **Skipped files.** `skipped-file` reads the `skipped_files` records reindex writes (see `internal/reindex`) through `Config.FileStates`. `NodeID` is the file path, since a file that never indexed has no node id. When the file's own node row is still indexed (it parsed once, then broke), the message says queries still serve that last good version.
- **Undeclared types.** `undeclared-type` reports one issue per node type used by indexed file rows but missing from the manifest, with the node ids as `Locations`; such nodes skip property validation entirely. It only runs when the manifest declares a node type of its own (the built-in sub-document types the loader merges in do not count), so a schemaless vault is not flagged.
- **Orphaned drift is never reported.** Workflow / property drift is only written while validating a live node, so a row whose node was deleted or renamed away is an orphan with no repair path. `Run` skips such rows at read time (a node-existence filter), and `reindex.Run` sweeps them from the drift tables (`DeleteOrphans`) so they do not accumulate. Together these stop doctor from pointing at ghost node ids forever.
- **Graph-expansion edge-types are validated with the query path's grammar** (`typeref.Parse`), so doctor agrees with what a real `--semantic` query does: a malformed entry (e.g. `Refs`) is flagged `graph-expansion-invalid-edge` (it hard-fails every semantic query), a well-formed scoped ref like `:references` whose type is declared is not flagged, and an undeclared-but-well-formed name stays `graph-expansion-unknown-edge` (the walker silently skips it). `enabled=true` with an empty `edge-types` list is a `graph-expansion-no-edges` no-op.
- **`embed-retry`** surfaces embed-queue rows that have failed at least once (`attempts > 0`) with their attempt count and last error, so a persistently failing embedder is visible rather than hidden behind the queue-depth counter.
- **Embedding settings.** `embedding-drift` compares stored vectors with the configured vector key (model plus `num-ctx`), and the `embed-large-chunk` and oversize sub-unit checks measure against the configured `chunk-max-bytes`. `embedding-prefix-hint` is advice: the model belongs to a family trained with instruction prefixes (`nomic-embed-text`, `embeddinggemma`, `mxbai-embed-large`, `snowflake-arctic-embed`, `snowflake-arctic-embed2`, matched on the last path segment of the model name) and a prefix it expects is unset: for a two-sided family (nomic, embeddinggemma) either prefix, so a config with only one side set is flagged with the missing one; for a query-only family the query prefix. A prefix set explicitly to `""` in `tusk.toml` counts as a deliberate opt-out and silences that side (`Manifest.EmbeddingsKeyDefined` tells it apart from an absent key). The message names the strings from the model card, says how to opt out, and suggests measuring, since the gain depends on the vault.
