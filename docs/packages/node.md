# internal/node

Heart of the data layer. Parses markdown frontmatter, validates properties against the manifest, resolves `ref` properties + body wikilinks + HTML `<a href>` links into edges, and provides the write-side service used by both CLI commands and MCP tools.

## Public surface

- `ParseFile(relPath, content) (*Node, error)` — frontmatter → `Node` shape; ID is the relPath sans extension. `Node.BodyOffset` is the byte offset in `content` where `Body` starts (after frontmatter, leading blank lines, and any BOM), so sub-unit line numbers can count the whole file. An unquoted frontmatter wikilink (`assignee: [[people/jane]]`) decodes in YAML to a nested flow sequence, not a string; since no property type nests lists, `ParseFile` normalizes that exact `[[id]]` / `[[id|alias]]` shape back to the scalar string so it resolves like its quoted twin instead of dropping the whole file from the index (#692).
- `Service` — `Create`, `Modify`, `Move`, `Delete`; serialized via the workspace lock. `Create` and `Modify` write through the `file_state` lease, so the next reindex skips the page. Each one therefore leaves the index as a re-parse of the written bytes would: the node row, its edges, its path refs, and its sub-units. The sub-unit pass is the reindex worker's markdown one (`subunit.Parse`, `AssignLines`, `Sync.ApplyFile`), so new pages get sub-units, a new body replaces the old ones, and a frontmatter edit renumbers their lines (#782). `ServiceDeps.Manifest` drives it; `DepsFromIndex` sets it, and nil skips it.
- `ValidateProperties(*Node, NodeTypes) PropertyResult` — type / required / drift checks.
- `ResolveEdges(*Node, EdgeTypes) error` — frontmatter edge values → typed edges. Under a paths-only edge type (`EdgeType.PathsOnly`) whose `from` allows the page, a value is a workspace path instead: it goes to `Node.PathValues` for `PathRefs`, never to `Node.Edges`. A value `pathref.Declared` rejects stays an edge.
- `ResolveRefs(*Node, NodeTypes, RefLookup) RefResolutionResult` — refs + wikilinks → resolved edges.
- `MaterializeWikilinks(*Node, EdgeTypes)` — appends the body wikilinks [`internal/wikilink`](wikilink.md) extracts to every edge type declared with `wikilinks = true`. Replaces the former hardcoded `references` special case; the name of the target edge no longer matters and zero, one, or many edges may opt in. Called by both `Service` and the reindexer. The Obsidian aliased form `[[id|display]]` (and `[[id#S1|display]]`) links to `id`; the text after the first `|` is display only and is dropped for edge derivation and ref resolution, but preserved verbatim when a `tusk node move` rewrites the link on disk.
- `ResolveHTMLLinks(sourcePath, hrefs) []string` — turns an HTML node's raw `<a href>` values (collected into `Node.HTMLLinks` by `ParseHTMLFile`) into target node ids, resolving each path-relative href against the source file's directory. HTML node ids retain their extension, so `href="topic-map.html"` from `mml/index.html` resolves to `mml/topic-map.html`. Drops external URLs, protocol-relative links, in-page anchors, and links that escape the vault root; strips query/fragment; unique in first-seen order. The resolution is `pathref.Link`'s, shared with path refs.
- `MaterializeHTMLLinks(*Node, EdgeTypes)` — the HTML counterpart of `MaterializeWikilinks`: appends resolved `<a href>` targets to every `wikilinks = true` edge type. A no-op for markdown nodes (no `HTMLLinks`). Called by the reindexer, the path that indexes dropped-in HTML files.
- `PathRefs(*Node, file, EdgeTypes, linenum.Scheme) []index.PathRefRow` — the path refs a page records, once per edge type that sets `paths = true` and lists the page's type in `from`: the paths its body names (markdown code spans, links and images; HTML `<code>` outside `<pre>`, `<a href>` and `<img src>`, collected into `Node.HTMLCode`, `Node.HTMLLinks` and `Node.HTMLImages` by `ParseHTMLFile`), plus, under a paths-only type, its frontmatter values from `Node.PathValues` with the lines they are written on. `ResolveEdges` must have run. `file` is the whole file, so markdown lines count from its top. The rules live in [`internal/pathref`](pathref.md). The reindexer calls it for every page, and the service re-derives a page's refs wherever it rewrites the page's edges (create, modify, `ReindexSource`), because those writes stamp `file_state` and the next reindex skips the file. `Rename` re-derives the moved page's refs at its new path, since a relative link can name another path from there, and re-derives each referrer it rewrites, since a retargeted HTML href is a ref too. It leaves paths-only frontmatter values in referrers as written.
- `AddEdgeToFrontmatter(root, sourceID, edgeType, targetID, edgeTypes) error` — inserts an edge target under the edge-type key in the source's frontmatter, respecting cardinality (scalar for one-to-one / many-to-one; list for one-to-many / many-to-many). Atomic read-mutate-write; callers must hold the workspace lock.
- `RemoveEdgeFromFrontmatter(root, sourceID, edgeType, targetID, edgeTypes) error` — idempotent inverse; drops the key when the last target is removed.
- `ReindexSource(root, nodes, edges, refs, edgeTypes, nodeTypes, sourceID, lineNumbering) error` — re-parses the source file and upserts its resolved edges and path refs into the index under the source's real path. Used by `tusk edge add` / `tusk edge remove` to refresh the index after a frontmatter rewrite without waiting for the watcher.

## Notes

`ResolveRefs` falls back from `Properties` to `Edges` because `reindex.go` reorders the pipeline (`ResolveEdges` runs first there). `Service.Create` runs `ResolveRefs` before `ResolveEdges` to avoid the fallback. Two code paths with different value-source assumptions — handoff §residual to clean up by re-ordering reindex's pipeline.

The wikilink scanner lives in [`internal/wikilink`](wikilink.md), which also documents its known gaps around code spans and fences. It moved out of this package so `internal/subunit` no longer imports `node`, which lets the service run the sub-unit pass itself.
