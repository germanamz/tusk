# Phase 3 — TaskService Mutations + Auto-Rollup Emission

**Design reference:** `docs/superpowers/specs/2026-04-18-event-log-design.md`.
**Milestone:** v0.13 — Initiative: Event Log.

## Prerequisites

Phases 1 and 2 must be complete.

## Inherits from phases 1–2

- `events` table exists; `sqlite.EventRepo` writes rows and enforces retention.
- `domain.NewTaskCreatedEvent / NewTaskModifiedEvent / NewStatusChangedEvent / NewTaskClaimedEvent / NewTaskReleasedEvent / NewTaskCompletedEvent / NewTaskDeletedEvent` constructors are available, each returning `*domain.Event`.
- `service.WithActor` / `service.ActorFromContext` propagate the acting player.
- `RepoBundle.WriteTx` is a non-nil `WriteTxProvider` in production code paths. Test bundles built via `bundleFromStore` already wire it; bundles built with `&RepoBundle{…}` literals that exercise mutation paths need migration to `bundleFromStore` or an explicit `WriteTx`.
- `TaskService` still calls `bundle.Tasks.Create` / `bundle.Store.WithTaskTx` directly — no events are emitted anywhere yet.

## Goal

Refactor every `TaskService` mutation except `Start` and `Pop` (those land in phase 4) so that:

1. The repo write and the event insert happen atomically inside `bundle.WriteTx.WithTx`.
2. Each mutation emits exactly the event type dictated by its action semantics, even when the underlying field change would also be describable as `task_modified` or `status_changed`.
3. Auto-complete and auto-revert cascades emit `status_changed` events with `source="auto_complete"` or `"auto_revert"` for every task they transition.

The split between "action-intent" events (`task_claimed`, `task_completed`, `task_deleted`, etc.) and "generic" events (`task_modified`, `status_changed`) is preserved by extracting a shared helper used by every mutation. The helper does not emit events — callers emit the event that matches their action.

After this phase, direct callers to `s.Update`, `s.Complete`, `s.Delete`, `s.Claim`, `s.Release` emit exactly one action-specific event per call (plus any status_changed events generated by cascading auto-complete/auto-revert).

## Background: current delegation pattern

Today, `TaskService.Claim`, `TaskService.Release`, `TaskService.Complete`, `TaskService.Delete`, and `TaskService.Start` all call `TaskService.Update` internally with a `domain.TaskUpdate`. `TaskService.Update` (service/task.go:408–554) does:

1. Load the task, version check, copy fields from `upd` onto `task`.
2. Validate title/priority, parent cycle, project existence, status transition against workflow.
3. Set `task.ModifiedAt`.
4. If the status changed, open `bundle.Store.WithTaskTx`, call `txTaskRepo.Update`, then `checkAutoComplete` and `checkAutoRevert`.
5. Otherwise, call `bundle.Tasks.Update` directly (no tx).

If the action-specific methods keep delegating to `Update` after `Update` emits events, a `Complete` call would emit `status_changed` (from Update) *and* `task_completed` (from Complete). This phase fixes that by extracting a non-emitting helper.

## Tasks

### 3.1 — Extract non-emitting helper `applyValidatedUpdate`

Add a new method on `TaskService`:

```go
// applyValidatedUpdate writes an already-validated task through tx.Tasks(),
// then runs the auto-complete and auto-revert cascades. It does not emit
// events for the primary task — callers emit the action-specific event.
// It DOES emit status_changed events inside the cascades (see task 3.3).
//
// task must carry the post-update field values and be version-matched;
// oldStatus is the status before the update so the cascades can decide
// whether to fire.
func (s *TaskService) applyValidatedUpdate(
    ctx context.Context,
    tx WriteTx,
    task *domain.Task,
    oldStatus string,
) (*domain.Task, error) {
    tr := tx.Tasks()
    if err := tr.Update(ctx, task); err != nil {
        return nil, err
    }
    updated, err := tr.GetByID(ctx, task.ID)
    if err != nil {
        return nil, err
    }
    if updated.Status != oldStatus {
        if err := s.checkAutoComplete(ctx, updated, tx); err != nil {
            return nil, err
        }
        if err := s.checkAutoRevert(ctx, updated, oldStatus, tx); err != nil {
            return nil, err
        }
    }
    return updated, nil
}
```

Change the signatures of `checkAutoComplete` and `checkAutoRevert` from taking `repository.TaskRepository` to taking `WriteTx`. Inside each, replace `txTaskRepo.Update(parent)` with:

```go
prevParentStatus := parent.Status // for auto-revert this is already computed
parent.Status = <target>
parent.ModifiedAt = time.Now().UTC().Truncate(time.Millisecond)
if err := tx.Tasks().Update(ctx, parent); err != nil { return fmt.Errorf(...) }

actor := ActorFromContext(ctx)
roles, err := s.workflowSvc.GetRoles(ctx, wfName, parent.Status) // add a helper if not present; see note below
if err != nil { return err }
source := "auto_complete" // or "auto_revert" in checkAutoRevert
evt := domain.NewStatusChangedEvent(parent, prevParentStatus, parent.Status, roles, source, actor)
if err := tx.Events().Record(ctx, evt); err != nil { return fmt.Errorf(...) }
```

`WorkflowService` already exposes `GetStatusByRole(ctx, wfName, role)` and `IsTransitionAllowed`. If a "get the roles attached to a status" accessor does not yet exist, add `WorkflowService.GetStatusRoles(ctx, wfName, status string) ([]string, error)` as part of this task — check `service/workflow.go` before adding to avoid duplication.

### 3.3 — Refactor `Update` and integrate auto-rollup source

Replace the current tx/non-tx branching tail of `Update` (service/task.go:528–553) with a unified path:

```go
actor := ActorFromContext(ctx)
statusChanged := task.Status != oldStatus

// Compute non-status field changes against `task` vs. the pre-update
// snapshot. Collect them into a map[string]FieldChange (nil if no changes).
changes := diffTaskFields(/* pre-update snapshot */, task)

var result *domain.Task
err := bundle.WriteTx.WithTx(ctx, func(tx WriteTx) error {
    updated, err := s.applyValidatedUpdate(ctx, tx, task, oldStatus)
    if err != nil {
        return err
    }
    result = updated

    if statusChanged {
        wfName, err := s.workflowName(ctx, /* project — already fetched above */)
        if err != nil { return err }
        roles, err := s.workflowSvc.GetStatusRoles(ctx, wfName, updated.Status)
        if err != nil { return err }
        if err := tx.Events().Record(ctx, domain.NewStatusChangedEvent(updated, oldStatus, updated.Status, roles, "user", actor)); err != nil {
            return err
        }
    }
    if len(changes) > 0 {
        if err := tx.Events().Record(ctx, domain.NewTaskModifiedEvent(updated, changes, actor)); err != nil {
            return err
        }
    }
    return nil
})
if err != nil { return nil, err }
return result, nil
```

Implementation notes:

- Compute the pre-update snapshot by copying the original `task` loaded at the top of `Update` *before* any field is overwritten by the `upd` spread (lines 420–471 in the current file). The simplest way is to snapshot the relevant fields into local vars at that point (`origTitle := task.Title`, `origPriority := task.Priority`, etc.) and pass them to a `diffTaskFields(orig, task)` helper.
- `diffTaskFields` lives in `service/task.go` as an unexported helper. It returns a `map[string]domain.FieldChange` keyed by JSON field name (`"title"`, `"priority"`, `"due_at"`, `"claimed_by"`, etc.). Compare: `title`, `description`, `priority`, `parent_id`, `project_id`, `due_at`, `wait_until`, `recurrence_rule`, `claimed_by`, `claimed_at`, `order`, `uda` (deep-equal for map). Do **not** include `status` — status changes flow through the `status_changed` event only.
- Order events: emit `status_changed` before `task_modified` when both fire. This is cosmetic but keeps replay in a predictable order.

### 3.4 — Refactor `Claim` and `Release`

Rewrite `TaskService.Claim` (service/task.go:636–673) so it no longer calls `s.Update`:

```go
func (s *TaskService) Claim(ctx context.Context, shortID, playerID string, version int) (*domain.Task, error) {
    players, err := s.playerRepo(ctx)
    if err != nil { return nil, err }
    if players == nil { return nil, fmt.Errorf("player support not configured") }
    if _, err := players.GetByID(ctx, playerID); err != nil {
        return nil, fmt.Errorf("player %q: %w", playerID, err)
    }

    bundle, task, err := s.bundleForShortID(ctx, shortID)
    if err != nil { return nil, err }
    if task.Version != version { return nil, domain.ErrConflict }
    if task.ClaimedBy != nil && *task.ClaimedBy != playerID {
        return nil, domain.ErrTaskClaimed
    }

    now := time.Now().UTC().Truncate(time.Millisecond)
    claimedBy := playerID
    task.ClaimedBy = &claimedBy
    task.ClaimedAt = &now
    task.ModifiedAt = now

    actor := ActorFromContext(ctx)
    oldStatus := task.Status // unchanged by claim
    var result *domain.Task
    err = bundle.WriteTx.WithTx(ctx, func(tx WriteTx) error {
        updated, err := s.applyValidatedUpdate(ctx, tx, task, oldStatus)
        if err != nil { return err }
        result = updated
        return tx.Events().Record(ctx, domain.NewTaskClaimedEvent(updated, playerID, actor))
    })
    if err != nil { return nil, err }
    players.UpdateLastSeen(ctx, playerID) //nolint:errcheck
    return result, nil
}
```

Rewrite `TaskService.Release` (service/task.go:676–711) symmetrically: validate claimant, clear `task.ClaimedBy` and `task.ClaimedAt`, open `WriteTx`, run `applyValidatedUpdate`, emit `domain.NewTaskReleasedEvent(updated, playerID, actor)`. Update `players.UpdateLastSeen` after the tx.

Neither method changes task status, so `applyValidatedUpdate`'s cascade is a no-op. The claim event carries `claimed_by`; the release event carries `released_by`.

### 3.5 — Refactor `Complete` and `Delete`

Rewrite `TaskService.Complete` (service/task.go:714–736) so it performs the full update locally:

```go
func (s *TaskService) Complete(ctx context.Context, shortID string, version int) (*domain.Task, error) {
    bundle, task, err := s.bundleForShortID(ctx, shortID)
    if err != nil { return nil, err }
    if task.Version != version { return nil, domain.ErrConflict }

    project, err := s.projectRepo.GetByID(ctx, task.ProjectID)
    if err != nil { return nil, fmt.Errorf("loading project %v: %w", task.ProjectID, err) }
    wfName, err := s.workflowName(ctx, project)
    if err != nil { return nil, err }
    doneStatus, err := s.workflowSvc.GetStatusByRole(ctx, wfName, domain.RoleDone)
    if err != nil { return nil, fmt.Errorf("resolving done status: %w", err) }

    allowed, err := s.workflowSvc.IsTransitionAllowed(ctx, wfName, task.Status, doneStatus)
    if err != nil { return nil, fmt.Errorf("checking transition: %w", err) }
    if !allowed {
        return nil, fmt.Errorf("transition %q → %q not allowed: %w", task.Status, doneStatus, domain.ErrInvalidTransition)
    }

    oldStatus := task.Status
    task.Status = doneStatus
    task.ModifiedAt = time.Now().UTC().Truncate(time.Millisecond)

    actor := ActorFromContext(ctx)
    var result *domain.Task
    err = bundle.WriteTx.WithTx(ctx, func(tx WriteTx) error {
        updated, err := s.applyValidatedUpdate(ctx, tx, task, oldStatus)
        if err != nil { return err }
        result = updated
        return tx.Events().Record(ctx, domain.NewTaskCompletedEvent(updated, oldStatus, actor))
    })
    if err != nil { return nil, err }
    return result, nil
}
```

Rewrite `TaskService.Delete` symmetrically, resolving the `RoleDelete` status and emitting `domain.NewTaskDeletedEvent(updated, oldStatus, actor)`.

Neither method emits `status_changed` directly — the action-specific event is the record of truth for these terminal transitions. The cascade inside `applyValidatedUpdate` does emit `status_changed(source="auto_complete")` for any parent that rolls up as a consequence.

### 3.6 — Tests

Extend `service/task_test.go` (or create `service/task_events_test.go` if the file grows too large) with the following. Use the existing `newSeededBundle` / `newTestBundle` helpers; they already populate `WriteTx` per phase 2.

1. **`Create` emits `task_created`**: call `Create`, then query the event repo (via the same store's DB, e.g., `sqlite.NewEventRepo(store.DB(), 10000, 1000).List(ctx, EventFilter{Type: ptr(EventTaskCreated)})`). Assert exactly one event, correct `EntityID`, payload fields. With `WithActor(ctx, "german")`, assert `PlayerID` is `"german"`; without, assert `nil`.
2. **`Update` emits `task_modified` when only non-status fields change.** Assert no `status_changed` event and payload `changes` contains only modified keys.
3. **`Update` emits `status_changed` with `source="user"` when only status changes.** Assert no `task_modified`.
4. **`Update` emits both when status + other fields change.** Assert `status_changed` fires first, then `task_modified`.
5. **`Claim` emits `task_claimed`**, carries correct `claimed_by`; does not emit `task_modified` despite changing `claimed_by` and `claimed_at` fields.
6. **`Release` emits `task_released`** with correct `released_by`.
7. **`Complete` emits `task_completed`**, with `prev_status`; does not emit `status_changed`.
8. **`Delete` emits `task_deleted`**, with `prev_status`; does not emit `status_changed`.
9. **Auto-complete cascade emits `status_changed(source="auto_complete")` for each rolled-up ancestor.** Set up a parent with auto-complete trigger; `Complete` the last remaining child; assert: one `task_completed` for the child + one `status_changed` with `source="auto_complete"` for the parent, in that order.
10. **Auto-revert cascade emits `status_changed(source="auto_revert")`** in the inverse scenario.
11. **Actor propagation.** For each mutation, assert `PlayerID` matches `ActorFromContext(ctx)` as set via `WithActor`. When context has no actor, assert `PlayerID == nil`.

Use `t.Parallel()` where safe. For event-count assertions prefer counting per type rather than a global total, so adding a new event type in a later phase doesn't cascade test updates.

## User-visible behavior preserved

- Every CLI command and MCP tool that calls `Create`/`Update`/`Claim`/`Release`/`Complete`/`Delete` returns the same results to the user as before (task JSON, errors, version numbers). The only observable difference is that rows now appear in the `events` table.
- Auto-complete and auto-revert cascades trigger on the same conditions as before; the only difference is each cascade transition is now logged as `status_changed`.
- Optimistic-locking behavior unchanged: `domain.ErrConflict` still surfaces on a version mismatch before any event is written.
- `Start` and `Pop` still work exactly as they did before — they still call `s.Update` internally. Phase 4 rewrites them.

- **No new files.**
- **Modified files:**
  - `service/task.go` — adds `applyValidatedUpdate`, `diffTaskFields`; rewrites `Create`, `Update`, `Claim`, `Release`, `Complete`, `Delete`; updates `checkAutoComplete` and `checkAutoRevert` signatures from `repository.TaskRepository` to `WriteTx` and makes them emit `status_changed` events.
  - `service/workflow.go` — add `GetStatusRoles(ctx, wfName, status string) ([]string, error)` only if not already present.

  - `checkAutoRevert(ctx, task, oldStatus, tx WriteTx)` (was `repository.TaskRepository`).
  - These are unexported; no external caller is affected.
  - Public API of `TaskService` is unchanged — method names and signatures on `Create/Update/Claim/Release/Complete/Delete` are identical to pre-refactor.
- **No schema or config changes.**
- **No new dependencies.**
- **No bridge code.** Phase ends with a complete, self-consistent set of emitting mutations. `Start` and `Pop` still call `s.Update`, which now emits `status_changed(source="user")` — this is a tolerable overlap because phase 4 will be the one to silence it. It is not bridge code; it is simply the state of the world between phases.
