# [v0.14 P1] Convention doc + linter scaffold + rule 1

> Type: epic (phase parent)
> Milestone: v0.14
> Plan: docs/superpowers/plans/v014-naming-convention/01-convention-and-scaffold.md
> Spec: docs/superpowers/specs/2026-04-28-v0.14-naming-convention-design.md §1, §2

## What

Land the written convention (`STYLE.md`), a multichecker-shell linter
binary (`cmd/tusk-lint`), Makefile integration, and `varnamelen`
configured in `.golangci.yml` with twelve per-package path
exclusions covering every existing directory. After this phase
ships, `make lint` runs both `golangci-lint` and `tusk-lint` in CI
and finds zero new violations (everything is excluded). The codebase
compiles and tests pass with no behavior changes.

## Why

Phase 1 establishes the rule-1 enforcement surface and the analyzer
framework that Phase 2 plugs into. Without it, no rule can be
enforced and no per-package sweep can begin.

## Children

- P1-T1: Write STYLE.md
- P1-T2: Cross-reference STYLE.md from CONTRIBUTING.md
- P1-T3: Create cmd/tusk-lint multichecker shell
- P1-T4: Wire lint-tusk into Makefile
- P1-T5: Configure varnamelen with per-package exclusions
- P1-T6: Verify Phase 1 CI green

## Acceptance

- `STYLE.md` exists at repo root with all four rules and the style guide.
- `cmd/tusk-lint` binary builds and runs.
- `make lint` runs both `lint-go` and `lint-tusk`.
- `make build`, `make test`, `make lint` all pass against the unmodified codebase.

## Depends on

Base codebase only.

## Blocks
