## What

Add `lint-tusk` and `lint-go` targets to `Makefile`. Make the
existing `lint` target depend on both. `lint-go` runs
`golangci-lint run ./...`; `lint-tusk` runs the new
`cmd/tusk-lint` binary over `./...`.

## Why

Single hook (`make lint`) runs both linters. CI already invokes
`make lint`; no CI changes are needed once the Makefile is updated.

## Code references

- `Makefile` — locate the existing `lint` target (currently runs `golangci-lint run ./...`) and refactor.

## Acceptance

- `make lint-go` runs `golangci-lint run ./...`.
- `make lint-tusk` runs `cmd/tusk-lint` over the codebase.
- `make lint` depends on both `lint-go` and `lint-tusk`.
- `make lint` exits zero against the unmodified codebase (no analyzers registered yet, so tusk-lint reports no violations).
