## What Was Built

v0.4 is an architectural milestone that replaces database storage for projects and workflows with configuration-driven in-memory entities. A Viper-based config system loads settings from `~/.config/tusk/config.toml` with embedded defaults and environment variable overrides. MCP tool/resource visibility is now configurable.

## Key Features in Detail

### Configuration System

Viper-based loading with three layers (highest priority first):

1. Environment variables (`TUSK_*` prefix)
2. Config file (`~/.config/tusk/config.toml`)
3. Embedded defaults (`internal/config/default.toml` via `go:embed`)

The config file is auto-created with embedded defaults on first run if it doesn't exist.

#### Config Sections

| Section | Purpose |
|---------|---------|
| `[storage]` | Backend selection and DB path |
| `[urgency]` | Scoring weights (prepared for future use) |
| `[tui]` | Date format, color, tree indent, default sort |
| `[mcp]` | Disabled tool/resource groups and individual tools/resources |
| `[workflows.<name>]` | Workflow definitions with statuses and transitions |
| `[projects.<id>]` | Project definitions with workflow assignment and settings |

### Config-Based Projects

Projects moved from UUID-based DB entities to string-keyed config entries. The `projects` table is dropped. Task `project_id` is plain TEXT validated at the service layer.

| Before (v0.3) | After (v0.4) |
|---|---|
| `domain.Project` with UUID, version, DB fields | `domain.Project` with string ID, Workflow, Settings |
| `ProjectRepository` with CRUD | `ProjectRepository` with `GetByID`, `List` (read-only) |
| SQLite implementation | In-memory implementation backed by config |
| `tusk project create` CLI | Removed — projects defined in config |
| `tusk_project_create` MCP tool | Removed |

### Declarative Workflows

Workflows moved from DB tables (`workflows`, `workflow_transitions`) to TOML config. The builtin `kanban` workflow provides the default.

| Before (v0.3) | After (v0.4) |
|---|---|
| `domain.Workflow` with UUID, ProjectID | `domain.Workflow` with Name, Statuses, Transitions |
| `domain.WorkflowTransition` with UUID, WorkflowID | `domain.WorkflowTransition` with FromStatus, ToStatus |
| `WorkflowRepository` with CRUD + UUID lookups | `WorkflowRepository` with `GetByName`, `List` (read-only) |
| SQLite implementation + seed data | In-memory implementation backed by config |
| `WorkflowService` methods take `projectID` | `WorkflowService` methods take `workflowName` only |
| `TaskTxProvider` passes `WorkflowRepository` in tx | `TaskTxProvider` passes only `TaskRepository` |
| No CLI commands | `tusk workflow list`, `tusk workflow info` |
| No MCP tool | `tusk_workflow_list` |

New `WorkflowService` methods:
- `List(ctx)` — all workflows
- `GetByName(ctx, name)` — single workflow
- `GetWorkflowWithProjects(ctx, name)` — workflow + referencing project IDs

### MCP Configurability

Tools and resources can be hidden by group or individually via config:

```toml
[mcp]
disabled_tool_groups = ["workflow"]
disabled_tools = ["tusk_task_tree"]
disabled_resource_groups = ["task"]
disabled_resources = ["tusk://projects/{name}/workflow"]
```

Config validation rejects unknown tool/resource names at startup.

## Architecture

### New Package: `internal/inmem`

In-memory repository implementations backed by config data:

```
internal/inmem/
  ├── project.go           — ProjectRepository (GetByID, List)
  ├── project_test.go
  ├── workflow.go           — WorkflowRepository (GetByName, List)
  └── workflow_test.go
```

### Simplified SQLite Layer

```
internal/sqlite/
  ├── store.go             — WithTaskTx simplified (no WorkflowRepository param)
  ├── task.go              — unchanged
  └── task_test.go         — unchanged
```

Deleted: `internal/sqlite/workflow.go`, `internal/sqlite/workflow_test.go`, `internal/sqlite/project.go`, `internal/sqlite/project_test.go`.

### DI Wiring (`cmd/tusk/main.go`)

```go
// v0.3
projectRepo := sqlite.NewProjectRepo(db)
workflowRepo := sqlite.NewWorkflowRepo(db)
workflowSvc := service.NewWorkflowService(workflowRepo)

// v0.4
projectRepo := inmem.NewProjectRepository(cfg.Projects)
workflowRepo := inmem.NewWorkflowRepository(cfg.Workflows)
workflowSvc := service.NewWorkflowService(workflowRepo, projectRepo)
```

## Database Changes

### Tables Removed

| Table | Reason |
|-------|--------|
| `projects` | Config-driven in-memory entities |
| `workflows` | Config-driven in-memory entities |
| `workflow_transitions` | Embedded in workflow config |

### Current Schema (5 tables)

```
tasks                  — core task entities (project_id is plain TEXT)
annotations            — timestamped notes per task
relations              — typed edges (blocks, relates_to, duplicates)
tags                   — tag definitions with optional color
tag_assignments        — many-to-many task-tag
```

### Known Limitations (carried from v0.3)

- **No quoted string support in filters** — `title:"my task"` and `description:` filters blocked until the lexer supports quoted strings
- **No boolean operators** — filters are AND-only; OR only within comma-separated values
- **No pagination** — `tusk list` returns all matching tasks
- **No sorting** — tasks returned in `created_at` order (urgency sorting is v0.6)
