# v0.13 — Roadmap Self-Host

Make tusk usable as the source of truth for its own roadmap. The hand-edited `ROADMAP.md` is replaced by a tusk project (`tusk-roadmap`) that regenerates the file via `make roadmap`. Eight initiatives shipped to get there: Event Log, Task Level Taxonomy, Sibling Ordering, Subtree Urgency Overrides, Progress Rollup, Data Portability, ROADMAP.md Migration, and Repo-Root Tusk Workspace.

### Highlights

**Event Log (foundational)**
- New `events` table; every task and relation mutation records exactly one event inside the same `WriteTx` as the row write — an event without a row (or vice versa) is structurally impossible
- Typed payloads: `task_created`, `task_updated`, `task_moved`, `task_resequenced`, `task_completed`, `task_deleted`, `relation_added`, `relation_removed`
- Forward-compat: unknown event kinds round-trip through `domain.UnknownPayload` so future-version dumps import cleanly
- Drives the v0.15 undo and webhook stories; v0.13 only ships the recording surface

**Task Level Taxonomy**
- Per-project ordered list of allowed `level` values (e.g. `milestone > initiative > story > task`)
- Parent-child rank constraint enforced on `Update`; child cannot outrank parent
- New `level=` filter; `tusk task level-check` validation command
- `tusk project modify level=…` and `tusk_project_modify` MCP `task_levels` array
- Replaces the originally-planned UDA Schema Validation initiative — the generic schema layer was scope-cut for v0.13 and is now tracked for v0.15

**Sibling Ordering**
- New `task_order` REAL column on `tasks`; backfilled by ID order
- `tusk task move` — Position enum (`--before`, `--after`, `--first`, `--last`) with optional `--parent` re-home
- `tusk task resequence` — recovers from float-gap exhaustion by collapsing a parent's children to dense integers
- `tusk_task_move` and `tusk_task_resequence` MCP tools
- `order=` filter; `order` field surfaced in JSON renderers
- Cycle detection on cross-parent moves via single recursive CTE

**Subtree Urgency Overrides**
- New `urgency_overrides` JSON column on `tasks` (`map[string]float64`)
- Ancestor-walk resolution: nearest ancestor (or self) with overrides wins; merges over the workspace default weights
- RFC 7396 merge-patch semantics on `tusk task modify`: `urgency.priority_weight=2.5` sets, `urgency.priority_weight=` clears one key, `urgency.clear` resets the whole map
- `tusk_task_modify` MCP gains `urgency_overrides` (object) and `urgency_overrides_clear` (bool)
- Renderer surfaces effective weights and which ancestor contributed each override

**Progress Rollup**
- `domain.AggregateRollup` — pure function over a slice of descendants and a workflow-resolver; returns `Rollup{Done, Total, ByStatus}`
- v0.9 status roles drive the math: `delete`-role tasks excluded entirely; `done`-role tasks count toward both `Done` and `Total`
- `tusk task tree --rollup` — branch nodes annotate with `[done/total done, %]  (status: count, ...)` using the seed workflow's full status order
- `tusk task summary` — single (`<short_id>`), filter, or roots modes; `--full` decouples descendant scope from block selection
- `tusk_task_summary` MCP tool — same envelope as the CLI; `short_id` > `filter` > structured params precedence

**Data Portability**
- `tusk export` / `tusk import` — bidirectional JSON; deterministic output (sorted keys, stable ordering, ms-truncated timestamps)
- Three modes: default (fail-fast on collision), `--replace` (row-level upsert), `--truncate` (wipe-and-restore; requires --replace), `--dry-run` (validation pass + counts)
- Single-tx apply — the entire import including the `workspace_imported` event commits or rolls back as one
- Schema-version awareness; `domain.UnknownPayload` lets a v0.13 build ingest a future-version dump without dropping events
- CSV explicitly deferred — JSON satisfies the dogfood path

**ROADMAP.md Migration**
- The hand-edited `ROADMAP.md` is gone; the file is regenerated from `tusk task tree project=tusk-roadmap --format markdown`
- New markdown renderer: H1 from project title, `> ` blockquote for description, H2/H3/bullets for the task tree, `**Annotations:**` / `**Notes:**` sub-blocks per task, project-scoped notes block under H1
- Inline tokens after task name use the same lexer as the inline-field CLI: `status=`, `level=`, `priority=`, `due=`, `order=`, `uda.*=`, `+tag`
- New `project_description` column on `projects`
- `make roadmap` target rebuilds `bin/tusk` and atomically regenerates the file
- Multi-project markdown trees rejected; an empty workspace emits no output

**Repo-Root Tusk Workspace**
- `tusk.toml` and `.data/tusk.db` live at the repo root — the dogfood roadmap travels in the same git tree as the code
- New layered e2e harness (`Env` + `MCPEnv`) ensures walk-up tests cannot see the dogfood DB; corruption from harness leakage is structurally prevented
- `TUSK_DB` env var dropped — workspace discovery is the single source for DB location
- First cutover attempt was reverted (`63f8327`) after the e2e suite picked up the dogfood DB; the layered harness rebuild and second cutover landed clean. Retrospective at `docs/retrospectives/v0.13-architecture-audit.md`

### Breaking Changes

- **`TUSK_DB` env var removed.** Use the `--db` flag or workspace discovery (`tusk.toml` walk-up). Existing scripts that set `TUSK_DB` need to be updated.
- **`ROADMAP.md` is now machine-generated.** Hand edits will be overwritten by the next `make roadmap`. The file is committed as a derived artifact; PR diffs that touch it should regenerate, not patch.
- New columns added via migrations 009–013. The migration chain runs forward cleanly; downgrades are supported on the `*.down.sql` side but lose all event log data and per-task overrides/orders/levels.
- The CLI surface is purely additive: `tusk task move`, `tusk task resequence`, `tusk task summary`, `tusk task level-check`, `tusk export`, `tusk import`. No existing commands changed flag shape.
- The MCP surface gains three tools (`tusk_task_move`, `tusk_task_resequence`, `tusk_task_summary`); no existing tool's inputs changed shape.

### Usage

```bash
# Sibling ordering — moves are inline-syntax friendly
tusk task move a3f8 --before b2c1
tusk task move a3f8 --after b2c1
tusk task move a3f8 --first --parent c4d5
tusk task move a3f8 --last
tusk task resequence c4d5         # recover from gap exhaustion

# Task levels — set per-project taxonomy, then constrain children
tusk project modify roadmap level=milestone level=initiative level=story level=task
tusk task create "Pricing redesign" level=initiative project=roadmap
tusk task level-check a3f8 level=task     # validates without committing

# Subtree urgency overrides — pin weights at any ancestor
tusk task modify a3f8 urgency.priority_weight=2.5 urgency.due_weight=1.5
tusk task modify a3f8 urgency.priority_weight=                # clear one key
tusk task modify a3f8 urgency.clear                           # clear all

# Progress rollup — branch badges and standalone summaries
tusk task tree --rollup
tusk task tree --rollup --all                       # include delete-role nodes in rendering
tusk task summary a3f8                              # single subtree
tusk task summary level=story                       # per-story rollup of stories
tusk task summary level=story --full                # blocks = stories; full subtree counted
tusk task summary                                   # workspace-wide; blocks = roots

# Data portability — bidirectional JSON
tusk export -o /tmp/workspace.json
tusk import /tmp/workspace.json --dry-run
tusk import /tmp/workspace.json --replace
tusk import /tmp/workspace.json --replace --truncate

# Roadmap regeneration
make roadmap                                        # writes ROADMAP.md atomically
```

### MCP Examples

```json
// tusk_task_move
{"short_id": "a3f8", "version": 4, "position": "before", "target_short_id": "b2c1"}

// tusk_task_resequence
{"parent_short_id": "c4d5"}

// tusk_task_summary — three modes, mutually exclusive
{"short_id": "a3f8"}                                // single
{"filter": "level=story"}                            // filter
{}                                                   // roots
{"short_id": "a3f8", "full": true}                   // INVALID_ARGUMENT

// tusk_task_modify with urgency overrides
{"short_id": "a3f8", "version": 4,
 "urgency_overrides": {"priority_weight": 2.5, "due_weight": null}}
{"short_id": "a3f8", "version": 4, "urgency_overrides_clear": true}
```
