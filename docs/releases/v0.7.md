# v0.7 — Player Management

Track which player (human or agent) is working on which task, prevent overlapping work, and pop the next best task from the queue in a single atomic operation.

### Highlights

**Player Registration**
- Players self-register by providing an ID on any action (`--player` CLI flag, `player_id` MCP parameter)
- Explicit registration via `tusk player register <id> --type human|agent`
- `last_seen_at` liveness tracking updated on every action

**Task Claiming**
- `tusk claim <id>` / `tusk release <id>` for explicit claim management
- Auto-claim on `tusk start` if unclaimed; rejects if claimed by another player
- Idempotent re-claim by the same player
- Claims preserved after `done`/`delete` for historical attribution
- `claimed_by:<player_id>` and `unclaimed:true` filter support

**Task Queue**
- `tusk available` — lists unclaimed, actionable (pending/active), unblocked, non-waiting tasks sorted by urgency
- `tusk pop` — atomically finds highest-urgency available task, claims it, and starts it
- Optimistic retry on contention — if another player grabs the top task, tries the next one
- Optional filter narrowing: `tusk pop project:backend --player agent-1`

**MCP Tools**
- `tusk_player_register` — register a player
- `tusk_task_claim` / `tusk_task_release` — claim and release tasks
- `tusk_task_available` — list available tasks
- `tusk_task_pop` — atomic pop from queue
- `player_id` parameter on `tusk_task_start` for auto-claim
- Optional `player_id` on read tools for liveness tracking

### CLI Changes

New commands:

```
tusk player register <id> --type human|agent
tusk claim <short_id> --player <id>
tusk release <short_id> --player <id>
tusk available [filters...] --player <id>
tusk pop [filters...] --player <id>
```

New global flag:

```
--player <id>
```

New filter fields:

```
claimed_by:<player_id>
unclaimed:true
```

### MCP Changes

New tools: `tusk_player_register`, `tusk_task_claim`, `tusk_task_release`, `tusk_task_available`, `tusk_task_pop`

Modified tools: `tusk_task_start` accepts optional `player_id`; all read tools accept optional `player_id` for liveness

Modified responses: all task responses include `claimed_by` and `claimed_at` fields

### Database Changes

New migration `007_players`:
- `players` table (id, type, registered_at, last_seen_at)
- `tasks.claimed_by` column (FK to players)
- `tasks.claimed_at` column

### Design Decisions

- **Self-declared player ID** — consumers own their naming; no resolution burden
- **Hard reject on claim conflict** — `ErrTaskClaimed`, no force-steal or TTL; stale player management is the consumer's concern
- **Claims preserved on done/delete** — historical attribution over automatic cleanup
- **Optimistic retry for pop** — consistent with existing concurrency model; urgency scoring stays in Go
- **"Not blocked" = no incomplete blockers** — completed/deleted blockers don't prevent availability
- **Pop claims + starts** — one operation for agents; finer control via separate claim/start
