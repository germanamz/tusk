# v0.4 — Configuration & Customization

Tusk is now fully config-driven. Projects and workflows move out of the database into `config.toml`, MCP visibility is configurable, and the database schema is simplified from 7 tables to 5.

### Highlights

**Configuration System**
- Viper-based config loading from `~/.config/tusk/config.toml` with embedded defaults and `TUSK_*` environment variable overrides
- Config file auto-created with defaults on first run
- Sections for storage, urgency weights, TUI preferences, MCP visibility, workflows, and projects

**Config-Based Projects**
- Projects defined in `[projects.<id>]` TOML sections with workflow assignment and settings
- `projects` database table dropped — task `project_id` is plain TEXT validated at the service layer
- `ProjectRepository` simplified to read-only (`GetByID`, `List`) with in-memory implementation
- `tusk project create` CLI command and `tusk_project_create` MCP tool removed

**Declarative Workflows**
- Workflows defined in `[workflows.<name>]` TOML sections with statuses and transitions
- `workflows` and `workflow_transitions` database tables dropped
- `WorkflowRepository` simplified to read-only (`GetByName`, `List`) with in-memory implementation
- Domain types stripped of UUID/DB artifacts — workflows identified by name, transitions embedded
- `WorkflowService` no longer takes `projectID` — workflows are global entities
- `TaskTxProvider` simplified — no `WorkflowRepository` in transaction callback

**Workflow Commands**
- `tusk workflow list` — tabular view of all workflows with statuses
- `tusk workflow info <name>` — detailed view with transitions and referencing projects
- `tusk_workflow_list` MCP tool — full workflow data for agents
- All commands support `--output json`

**MCP Configurability**
- `[mcp]` config section to hide tools and resources by group or individually
- `disabled_tool_groups`, `disabled_tools`, `disabled_resource_groups`, `disabled_resources`
- Config validation rejects unknown entries at startup

### Breaking Changes

- `tusk project create` removed — define projects in `config.toml`
- `tusk_project_create` MCP tool removed
- Database migration rewrites `001_initial` — drops `projects`, `workflows`, and `workflow_transitions` tables
- `WorkflowService` constructor now requires `ProjectRepository` as second argument
- `WorkflowService` methods no longer accept `projectID` parameter
- `TaskTxProvider.WithTaskTx` callback receives only `TaskRepository` (no `WorkflowRepository`)
