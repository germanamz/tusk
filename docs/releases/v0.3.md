# v0.3 — MCP Server

Tusk now speaks MCP. This release adds a full Model Context Protocol server, letting AI agents in IDEs and other MCP clients create, query, and manage tasks programmatically over stdio transport.

### Highlights

**MCP Server**
- `tusk mcp serve` starts a stdio-transport MCP server — plug it into any MCP-compatible client (Claude Code, Cursor, etc.)
- 13 tools mapping 1:1 to service methods — agents get the same capabilities as the CLI
- 3 resource templates for read-only state access (`tusk://tasks/{id}`, `tusk://projects/{name}`, `tusk://projects/{name}/workflow`)
- Server instructions guide agents on tool naming and optimistic locking conventions

**Task Tools**
- `tusk_task_create` — full task creation with title, priority, project, parent, tags, due date
- `tusk_task_get` — rich response with tags, relations, and annotations in a single call
- `tusk_task_list` — structured filters (status, priority range, project, tags, due range, parent/subtree)
- `tusk_task_modify` — partial updates with `add_tags`/`remove_tags`, version required
- `tusk_task_start`, `tusk_task_done`, `tusk_task_delete` — status transitions with optimistic locking
- `tusk_task_annotate` — add timestamped notes
- `tusk_task_tree` — nested JSON tree with optional `include_deleted` flag

**Relation & Project Tools**
- `tusk_relation_add` / `tusk_relation_remove` — typed relations with enum validation
- `tusk_project_list` / `tusk_project_create` — project management for agents

**Agent-Friendly Error Handling**
- Domain errors map to `isError: true` tool results with actionable messages
- Version conflicts tell agents to re-fetch: `"version conflict: task was modified, re-fetch and retry"`
- Cycle detection, duplicate relations, and not-found errors all surface cleanly

**Optimistic Locking End-to-End**
- All task responses include `version`
- All mutation tools require `version` — stale versions are rejected
- Agents follow a fetch → mutate → retry pattern naturally
