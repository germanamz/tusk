# v0.9 — Workspace Scope Collapse

Every project declared in a Tusk config file now shares a single
workspace database. The per-project `db_path` field, which let
individual projects point at their own SQLite file, has been removed.
Cross-project queries and relations become first-class; the storage
registry and its fan-out machinery are gone.

## Breaking changes

### Per-project `db_path` removed

Projects no longer carry a `db_path` field. Every project declared in a
config file shares the single database declared by that file's
`storage.path`. Cross-project operations — `tusk list`, `tusk pop`,
`tusk available`, `tusk link` — now run as single-database queries, and
relations can span projects inside the same workspace.

Users who had set `[projects.<name>].db_path` in a previous version
should follow the manual migration procedure in
[docs/workspace-scope-migration.md](../workspace-scope-migration.md).
Unknown keys in the config are ignored on load, so a stale `db_path`
line will not break startup — but it will silently do nothing, which
is exactly the footgun the migration doc helps users avoid.

`tusk project create <name> workflow=kanban db-path=/foo.db` now
errors with `unknown field "db-path"`. Previously (briefly, in the
v0.9 development series) this was accepted and ignored. Scripts that
pass `db-path=` must drop the argument.

### Highlights

**Single-workspace runtime**
- `cmd/tusk/main.go` and `client.go` open exactly one `*sqlite.Store`
  and wire a single `*service.RepoBundle`. The multi-store resolver
  closure and its validation machinery are gone.
- `service.TaskService` and `service.RelationService` collapse their
  read paths to a single store. Cross-project relations are permitted.
- `sqlite.StoreRegistry` is deleted. `sqlite.ResolveWorkspacePath` is
  the sole path helper for the workspace database.
- `domain.ErrCrossStoreRelation` is removed; its callers no longer
  exist.

**Config schema cleanup**
- `config.ProjectConfig` drops its `DBPath` field.
- `config.ProjectMutation` drops its `DBPath` field.
- `internal/tui` project parser no longer recognizes `db-path=` on
  `project create` or `project modify`.
