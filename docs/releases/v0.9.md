# v0.9 — Configuration Management

Turn tusk's TOML configuration into a managed surface. Inspect, mutate, and validate configuration through the CLI and MCP; full CRUD for workflows and projects; local `tusk.toml` discovery; and MCP hot-reload so agent-driven mutations take effect immediately.

### Highlights

**Config CLI**
- `tusk config show` — print effective config with active-file header (text or JSON)
- `tusk config path` — resolve the active config file, or `(not yet created)`
- `tusk config init [--local]` — scaffold global or project-local `tusk.toml` from defaults
- `tusk config get <dot.path>` — read a single value (`urgency.priority_weight`, `projects._default.workflow`)
- `tusk config set <dot.path> <value>` — atomic write-back through the same resolver; `--global` forces global target
- `tusk config validate` — file-only validation (no env overlay)
- `tusk config edit` — open the resolved file in `$VISUAL` / `$EDITOR`

**Workflow CRUD**
- `tusk workflow create <name> status=pending(initial,start) status=done(terminal) transition=pending:done`
- `tusk workflow modify <name> +status=review +transition=active:review,review:done`
- `tusk workflow delete <name>` — guarded when any project references the workflow
- Inline syntax supports role-tagged statuses (`initial`, `start`, `done`, `delete`, `terminal`) and `+`/`-` modifiers for add/remove

**Project CRUD**
- `tusk project create <name> workflow=kanban urgency.priority_weight=4.0 auto-complete.trigger=subtasks auto-complete.target=parent`
- `tusk project modify <name> +urgency.priority_weight=0.5 -urgency.due_weight workflow=…`
- `tusk project delete <name> [--force]` — blocks built-in default and any project referenced by tasks; `--force` overrides
- Urgency overrides accept absolute values and signed deltas in the same expression

**Local Config Discovery**
- Walk-up `tusk.toml` from CWD (git-style): first match in any ancestor wins
- `--config <path>` CLI flag and `TUSK_CONFIG` env var pin an explicit file (hard error if missing)
- Resolution order: **explicit file → walk-up → global → defaults**
- Single resolver powers the CLI, the programmatic `Client`, and the MCP server

**MCP Config / Workflow / Project Tools**
- `tusk_config_show` — effective config + source file path
- `tusk_config_set` — mutate any scalar key; `storage.*` is read-only
- `tusk_workflow_create` / `_modify` / `_delete` — structured JSON for statuses and transitions
- `tusk_project_create` / `_modify` / `_delete` — absolute `urgency` + signed-delta `urgency_delta`; `force` on delete
- All mutations serialize under a server-wide mutex
- **Hot reload**: on every mutation the server re-reads TOML and swaps workflow repo, project repo, and urgency engine in place — agents see the new config without a restart

**Role-based Workflow Statuses**
- Workflows are now defined by statuses with role flags (`initial`, `start`, `done`, `delete`, `terminal`) instead of hardcoded names
- `TaskService` looks statuses up by role, so `create`, `start`, `done`, `delete`, `available`, and `next` all work with user-defined workflows
- Default kanban workflow in `config/default.toml` is expressed in the new role format

**Inline Syntax: `:` → `=`**
- Filter and CLI inline syntax migrated from `key:value` to `key=value`
- `:` is now reserved for value modifiers (e.g. ordered transition pairs: `transition=pending:active`)
- Shared `syntax` package extracted from `filter` — single lexer, AST, and modifier registry feeding both filters and CLI inline syntax
- `Token.Modifier` byte exposes `+`/`-` prefixes cleanly; new modifiers become registry entries, not grammar changes

### Breaking Changes

- **Filter and inline syntax now use `=`** instead of `:`. All first-party tests, CLI help, and MCP descriptions have been migrated. Consumers with saved filter strings must update them.
- **`ProjectConfig.db_path` removed.** Per-project databases were briefly introduced during v0.9 and then reverted — the workspace is once again backed by a single SQLite file. Any `db_path` entries in existing `tusk.toml` files should be deleted.
- **Workflow TOML format is role-based.** `statuses = ["pending", "active", "done"]` no longer parses; statuses are now a map keyed by name with role flags. Run `tusk config init` against a fresh directory to see the new shape.

### Usage

```bash
# Inspect the active config and where it lives
tusk config path
tusk config show --format json

# Create a project-local config in the current repo
tusk config init --local

# Bump priority weight for a project by half a point
tusk config set projects.backend.urgency.priority_weight 4.5

# Or do the same through the project CLI with modifier syntax
tusk project modify backend +urgency.priority_weight=0.5

# Custom workflow end-to-end
tusk workflow create triage \
  status=new\(initial,start\) \
  status=investigating \
  status=resolved\(terminal\) \
  status=wont_fix\(terminal,delete\) \
  transition=new:investigating,investigating:resolved,investigating:wont_fix
tusk project create bugs workflow=triage
tusk add "Parser crashes on empty filter" --project bugs
```

Agents drive the same flows via MCP:

```jsonc
// Inspect
{ "name": "tusk_config_show" }

// Mutate
{ "name": "tusk_project_modify",
  "arguments": {
    "name": "backend",
    "urgency_delta": { "priority_weight": 0.5 }
  }
}
```

### Config Behavior

| Surface | Behavior |
|---|---|
| `--config <path>` | Hard error if the file does not exist |
| `TUSK_CONFIG=<path>` | Same as `--config`; the flag wins when both are set |
| Walk-up | CWD → ancestors; first `tusk.toml` wins |
| Global | `$XDG_CONFIG_HOME/tusk/config.toml` (or platform equivalent); missing is not an error |
| Defaults | Used when nothing else resolves |
| `tusk config set` | Writes to the same file the loader resolved; atomic temp-file + rename |
| MCP `tusk_config_set` | Same write path, plus hot reload of workflow / project / urgency state |

### Design Decisions

- **Single resolver for all surfaces** — CLI, `Client`, and MCP all route through `config.ResolveConfigFile` so "which file is active?" has one answer across the codebase.
- **Hot reload over restart** — MCP agents cannot restart their own server, so mutations rebuild the workflow repo, project repo, and urgency engine in place under the server mutex.
- **`storage.*` is not mutable via MCP** — swapping the database path mid-session would strand open handles. Operators edit the TOML and restart instead.
- **Atomic TOML writes** — every mutation writes to a temp file and renames into place; a killed process cannot leave behind half a config.
- **Inline syntax shares a lexer with filters** — the `syntax` package exists so workflow, project, and filter surfaces all parse the same way.
- **Role-based statuses** — the service layer no longer special-cases `"pending"` / `"active"` / `"completed"`; users can rename every status and everything still works.
- **Per-project databases dropped** — the complexity of cross-store relations outweighed the ergonomic win at this stage. Revisit post-v1 if multi-tenant demand appears.
