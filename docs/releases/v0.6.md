# v0.6 — Urgency & UX

Smart task prioritization and polished terminal experience. Tasks are now ranked by a weighted urgency score computed from 10 factors, and `tusk next` surfaces the most important actionable task in a single command.

### Highlights

**Urgency Scoring Engine**
- 10-factor weighted scoring: priority, due date (sigmoid curve), age, active status, blocking, blocked, tags, project, annotations, waiting
- All weights configurable via `[urgency]` config section and `TUSK_URGENCY_*` environment variables
- Per-project weight overrides with sparse merge — override one weight, inherit the rest
- `tusk list` sorted by urgency descending (highest urgency first)
- `urgency` field included in all JSON task responses (CLI and MCP)

**`tusk next` Command**
- Displays the highest-urgency actionable task (pending or active, not waiting, not blocked)
- Available as CLI command and `tusk_task_next` MCP tool
- Returns error when no actionable tasks exist

**Color-Coded Output**
- Priority levels colored (low=blue, medium=yellow, high=red, urgent=bold red)
- Status values colored (active=green, completed=dim, deleted=dim)
- Tag colors via `tusk tag modify <name> --color <hex>` and config defaults
- Respects `NO_COLOR` env var and `--no-color` flag

**Markdown Description Rendering**
- `tusk info` renders markdown descriptions using glamour (charmbracelet)
- Plain text fallback when color is disabled

**Advanced Filters**
- Quoted string support: `title:"some text"`, `description:"some text"`
- Boolean operators: `AND` / `OR` / `NOT` with parenthesized grouping

### CLI Changes

New commands:

```
tusk next                       # Show highest-urgency actionable task
```

Modified output:

```
tusk list                       # Now sorted by urgency, Urg column added
```

### MCP Changes

New tools:

- `tusk_task_next` — returns highest-urgency actionable task

Modified responses:

- All task responses include `urgency` float64 field
- `tusk_task_list` results sorted by urgency descending

### Configuration

New `[urgency]` weight fields:

```toml
[urgency]
priority_weight    = 6.0
due_weight         = 12.0
age_weight         = 2.0
active_weight      = 4.0
blocking_weight    = 8.0
blocked_weight     = -5.0
tags_weight        = 1.0
project_weight     = 1.0
annotations_weight = 1.0
waiting_weight     = -3.0
```

Per-project overrides (sparse merge — only specify what you want to change):

```toml
[projects.backend.settings.urgency]
blocking_weight = 15.0
```

### Design Decisions

- **In-memory scoring, not SQL** — sigmoid and conditional logic cleaner in Go; batch queries avoid N+1
- **Non-persisted Urgency field** — computed on read, avoids schema migration
- **Pointer fields for project overrides** — nil = inherit global, non-nil = override
- **Sigmoid constants not configurable** — k=0.5, midpoint=14 days are internal tuning; only weights are user-facing
- **`tusk next` includes active tasks** — "what should I focus on?" includes in-progress work
