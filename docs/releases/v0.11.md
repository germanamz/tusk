# v0.11 — CLI Command Grouping

Regroup the CLI under explicit subcommand namespaces and lock in the inline-field principle: every entity property flows through `key=value` syntax, never through ad-hoc Cobra flags. Pre-release, so all changes are a clean break — no backward-compat aliases.

### Highlights

**`tusk task` Subcommand Group**
- Every task-scoped verb moved under `tusk task`: create, list, get, modify, start, done, delete, tree, next, annotate, claim, release, available, pop, link, unlink
- Old flat commands (`tusk add`, `tusk list`, etc.) emit targeted "did you mean" errors via hidden stub commands
- Renamed: `tusk add` → `tusk task create`, `tusk info` → `tusk task get`
- MCP tools renamed in lockstep: `tusk_relation_add` → `tusk_task_link`, `tusk_relation_remove` → `tusk_task_unlink`

**Inline Field Principle**
- Entity properties use the shared `key=value` lexer — one way to set a field on a task
- Cobra flags reserved for invocation-level concerns only: `--player`, `--format`, `--config`, `--db`, `--no-color`, `--all`, `--force`, `--global`, `--local`, `--type`, `--color`, `--usage`

**String Field Input Unification**
- `--description` / `-d` flag removed from `tusk task create` and `tusk task modify`
- `description=` and `title=` flow through inline syntax with `@file` / `@-` expansion
- `description=@./spec.md` loads file content; `description=@-` reads stdin; `@@` escapes to literal `@`
- Mid-string expansion: `description="see @./notes.md for background"` splices file content inline
- Positional bodies gain `@` expansion: `tusk task annotate a3f8 @./notes.md`
- `[inline].max_expansion_size` config key (default 1 MB) caps per-reference expansion
- Binary files rejected via NUL-byte scan on first 8 KB

**UDA Flag Elimination**
- `--uda` / `-u` flag removed from `tusk task create` and `tusk task modify`
- `uda.key=value` inline syntax on create/modify (matches existing filter syntax)
- `uda.key=` (empty value) deletes a UDA key on modify
- Bare unknown fields (`env=prod`) are rejected with a "did you mean `uda.env`?" hint

**Shell Completion**
- `tusk completion bash|zsh|fish|powershell` generates shell completion scripts on demand
- No pre-baked artifacts — regenerate after each upgrade

### Usage

```bash
# Create with inline fields and @file expansion
tusk task create "Design spec" project=backend priority=3 +api description=@./spec.md

# UDA metadata (replaces --uda flag)
tusk task create "Deploy" uda.env=prod uda.region=eu
tusk task modify a3f8b2c1 uda.team=backend   # set
tusk task modify a3f8b2c1 uda.env=            # delete

# Description from stdin
cat spec.md | tusk task modify a3f8b2c1 description=@-

# Mid-string file expansion
tusk task modify a3f8b2c1 description="see @./notes.md for background"

# Escape literal @
tusk task modify a3f8b2c1 description="@@literal-at-sign"

# Annotation from file
tusk task annotate a3f8b2c1 @./investigation.md

# Shell completion (regenerate after upgrades)
tusk completion zsh > "${fpath[1]}/_tusk"
```

### Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| No backward-compat aliases | Old flat verbs error with "did you mean" | Pre-release; clean break avoids ambiguity and alias maintenance |
| Hidden stubs instead of `SuggestFor` | Explicit mapping table in `moved.go` | Exact match + targeted suggestion; Cobra's fuzzy matcher is a fallback |
| `@` expansion at consumer layer | No lexer/AST changes | Mid-string case (`"text @file"`) cannot be a stripped prefix marker; pure text pass is simpler |
| `@@` escape, not backslash | Matches convention (`$$` in Make, `%%` in batch) | Shell-friendly; `\@` interacts badly with shell quoting |
| Stdin once per invocation | `expandState` tracks consumption | Prevents confusion when both `title=@-` and `description=@-` appear |
| Unknown bare fields rejected | `env=prod` → "did you mean `uda.env`?" | Typos on UDA keys surface loudly instead of silently becoming UDAs |
