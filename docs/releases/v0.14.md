# v0.14 — Naming and Spacing Convention

Establish a project-wide naming and spacing convention for the Tusk codebase, enforce it mechanically with a custom Go static-analysis multichecker, and sweep every existing package to match. **No behavior changes** — pure readability and tooling.

The convention itself lives in `STYLE.md`. After this milestone, every package in the repository conforms to all four rules; `.golangci.yml` carries no per-package exclusions; no `//nolint:varnamelen` directives exist anywhere; `make lint-style-locked` guards both escape hatches in CI.

### Highlights

**Four Linter-Enforced Rules**
- **Rule 1** — No single-character identifiers anywhere (locals, parameters, receivers, loop indices, generic type parameters, **package names, and file names**). Includes `*testing.T`, `*testing.B`, `testing.TB`, short generic type parameters, and the analysistest stdlib convention of single-letter testdata packages — all renamed.
- **Rule 2** — Blank lines around `if err != nil` guards. The error-producing assignment, the guard itself, and the next statement are all visually separated.
- **Rule 3** — Named errors on `err` shadow. When two or more `err` variables share a lexical scope, **every** instance becomes `<noun>Err` (`blockingErr`, `annotationErr`, `noteErr`).
- **Rule 4** — Standardized test-handle parameter names: `test *testing.T`, `bench *testing.B`, `harness testing.TB`. Deviation fails the build.

Plus an advisory style guide for receiver-naming, generic type parameters, loop indices, and single-error functions — review-time guidance for cases the linter cannot mechanically check.

**`STYLE.md` — the canonical reference**
- Rule descriptions, rationale, before/after examples
- Advisory style guide for non-mechanical cases
- Enforcement summary mapping each rule to the tool that checks it
- Status header: "enforced repository-wide as of v0.14"

**`tusk-lint` Multichecker**
- New `cmd/tusk-lint` binary wraps three custom analyzers via `golang.org/x/tools/go/analysis/multichecker`
- `internal/lint/blankline` — rule 2
- `internal/lint/namederr` — rule 3
- `internal/lint/testhandle` — rule 4
- All three drive analysistest test suites with positive + negative fixtures

**`varnamelen` Configuration**
- `golangci-lint` runs with `varnamelen` enabled at strict settings: `min-name-length: 2`, `check-receiver: true`, `check-return: true`, `check-type-param: true`
- Zero per-package exclusion rules — every package conforms

**`make lint-style-locked` (Lock-in Guard)**
- New Makefile target — fails CI if either escape hatch tries to reintroduce `varnamelen` suppression:
  1. A `//nolint:varnamelen` directive in any tracked Go source file
  2. A `linters: [varnamelen]` exclusion rule in `.golangci.yml`
- Wired as a prerequisite of `make lint` so the structural check fails fast before the slower analyses
- Each failure prints the offending file:line and instructs the contributor to **rename the identifier** rather than suppress the linter

**Repository-Wide Sweep**
- Eight phases plus a P-CONFIG follow-up swept every Go package in the repo (`service/`, `internal/tui/`, `internal/mcp/`, `internal/portability/`, `filter/`, `domain/`, `syntax/`, `repository/`, `sqlite/`, `cmd/`, `tests/e2e/`, `config/`, root)
- ~5,300 individual rule violations resolved across ~93 PRs
- Test files swept in the same phase as their production code; rule 1 spans test handles, range variables, and table-driven test indices

### Breaking Changes

None for users of the tusk CLI or MCP surface — the milestone is pure refactor + tooling. Every rename is local to a function or method; no public API surface changed shape.

For contributors:

- `make lint` now runs `lint-style-locked` first — a pre-commit failure on `//nolint:varnamelen` or a `linters: [varnamelen]` rule will surface here before the longer-running analyses.
- The fix for any `varnamelen` warning is **always renaming the identifier**, never adding a suppression directive. `STYLE.md` is the canonical reference; the lock-in guard prevents regression.
- New contributor-facing files: `STYLE.md` (linked from `CONTRIBUTING.md`) and `cmd/tusk-lint`.

### Usage

```bash
# Run the full lint suite (structural guard → golangci-lint → tusk-lint)
make lint

# Run individual layers
make lint-style-locked
make lint-go
make lint-tusk

# Run a single custom analyzer in isolation
go run ./cmd/tusk-lint -blankline ./service/...
go run ./cmd/tusk-lint -namederr  ./internal/...
go run ./cmd/tusk-lint -testhandle ./tests/...
```

### What Doesn't Change

This milestone deliberately ships nothing user-visible:

- No new commands.

- No schema migrations.
- No CLI flag changes.
- No config-file additions.
- No e2e test additions (every existing e2e test passes unchanged).

### Acknowledgments

The sweep phases were orchestrated through subagent-driven implementation with two-stage review per task (spec compliance, then code quality). Implementer subagents repeatedly drifted toward terse abbreviations (`wf`, `evt`, `tc`, `tr`); the user feedback was consistent on what counted as "descriptive enough" — that feedback is now captured as the advisory style guide section in STYLE.md and as a hard rule in the orchestration prompts for future milestones.

The `config/` package was missing from the original spec audit; the P-CONFIG follow-up sweep landed before lock-in to keep P8's "all sweeps done" precondition clean.
