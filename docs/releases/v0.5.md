# v0.5 — Rich Content

Rich task descriptions and structured metadata for agent orchestration. Tasks can now carry user-defined attributes (UDAs) queryable via filter syntax, and descriptions can be loaded from files.

### Highlights

**File-Based Description Input**
- `--description @file.md` syntax on `tusk add` and `tusk modify` to read content from a file
- MCP tools already accepted full descriptions — no MCP change needed

**User-Defined Attributes (UDA)**
- `--uda key=value` repeatable flag on `tusk add` and `tusk modify`
- Merge semantics on modify: add/overwrite keys, empty value (`--uda key=`) removes a key
- UDA section displayed in `tusk info` with sorted keys and multi-line support
- `tusk_task_create` and `tusk_task_modify` MCP tools accept optional `uda` object parameter
- All MCP task tool responses now include `uda` field (previously missing)
- Domain validation: keys must match `^[a-zA-Z_][a-zA-Z0-9_-]*$`, all values must be strings

**UDA Filter Support**
- `uda.key:value` filter syntax for querying tasks by UDA key-value pairs
- `uda.key:` matches tasks where key is absent or empty
- Multiple `uda.*` filters are AND'd
- Backed by SQLite `json_extract` — no schema changes required

### CLI Changes

No new commands. UDA exposed through flags on existing commands:

```
tusk add "task" --uda env=prod --uda team=backend
tusk modify <id> --uda env=staging
tusk modify <id> --uda env=
tusk list uda.env:prod
tusk list uda.env:prod uda.team:backend
tusk list uda.env:
```

### MCP Changes

No new tools. Parameters added to existing tools:

- `tusk_task_create` — optional `uda` object parameter (all string values)
- `tusk_task_modify` — optional `uda` object parameter (merge semantics, empty string removes key)
- All task responses now include `uda` field

### Design Decisions

- **All UDA values are strings** — typed validation deferred to v0.9 UDA Schema Validation
- **Merge semantics, not replace** — prevents accidental data loss on modify
- **`json_extract` without index** — acceptable for expected data sizes; indexing deferred
- **MCP list does not gain UDA filter** — MCP uses explicit parameters, not filter syntax; UDA filter is CLI-only
- **No wildcards/patterns** — simple equality covers current needs; advanced filters deferred to v0.6
