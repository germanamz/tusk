# v0.12 — Trailing Window Notes

A persistent, append-only notebook scoped by project and player. Each note carries a markdown body, free-form metadata, and an optional task reference. Notes are never edited — only archived — and listings apply a **trailing window** so callers always see the most recent N entries, configurable per player and per project.

v0.12 also ships an **MCP field-restriction layer** that lets operators block individual input fields on enabled write tools, validated at startup and enforced at runtime.

### Highlights

**Note Entity and Storage**
- New `notes` table with composite `(project_id, player_id, created_at DESC)` index and a partial `task_id` index for task-scoped lookups
- `NoteRepository` interface with `Create`, `GetByID`, `FindByIDPrefix`, `Archive`, and window-aware `List`
- Window limit is applied at the SQL layer (`LIMIT N`), not post-fetch
- Soft archive via nullable `archived_at` column — notes are never deleted

**`tusk note` CLI**
- `tusk note add "<body>" [project=<name>] [meta.key=value...] [--task <short_id>]` — create a note, body supports `@file` / `@-` / literal text, metadata keys namespace under `meta.`
- `tusk note archive <id_or_prefix>` — archive a note by full UUID or 8+ character prefix; author-only
- `tusk note list [project=<name>]` with filters:
  - `--all-players` — every player's notes in the project
  - `--filter-player <id>` / `player=<id>` — a specific player
  - `--task <short_id>` — notes attached to one task
  - `--window <N>` — override the trailing window
  - `--since <duration>` — `7d`, `2w`, `24h`, `30m`, `45s` (extended duration grammar)
  - `--archived` — include archived notes
- Markdown bodies render with glamour in text mode; JSON output stays raw

**Trailing Window Resolution**
- Window size resolves through a four-tier chain: `--window` flag → `players.note_window_size` → `ProjectSettings.NoteWindowSize` → `[notes].window_size` → hardcoded `20`
- New `tusk player modify <id> note-window-size=<N>` sets the per-player override; `note-window-size=` clears it
- `tusk player info` surfaces the override when set

**Note MCP Tools**
- `tusk_note_add` — create a note; optional `project`, `task` (short ID), `metadata` (object)
- `tusk_note_list` — same filter surface as CLI (`target_player_id`, `all_players`, `task`, `window`, `since` as RFC 3339, `include_archived`)
- `tusk_note_archive` — archive by full UUID; author-only (non-author returns `forbidden: archive note`)
- Participates in `[mcp].disabled_tool_groups` via a new `note` group

**MCP Field Restrictions**
- New `[mcp.blocked_fields]` config section maps tool names to lists of input fields an agent may not supply
- Hand-maintained tool-field registry (`internal/mcp/field_registry.go`) enumerates every declared input for every write tool
- **Startup validation** rejects unknown tool names, unknown fields, and dotted sub-keys
- **Runtime enforcement** at the top of every mutating MCP handler — absent keys and explicit `null` pass through; any non-nil supplied value in the blocklist returns a deterministic, sorted error listing the offending fields
- **Hot-reloadable**: `cfgMu` guards the blocklist so config reloads swap the policy without restarting the server
- **Default policy** locks down the two fields an agent could use to reshape the workspace regardless of top-level tool disables:
  - `tusk_project_modify = ["workflow"]`
  - `tusk_project_delete = ["force"]`

**Extended Duration Grammar**
- New `filter.ParseRelativeDuration` parses `Nd` (days) and `Nw` (weeks) in addition to Go's standard units (`h`, `m`, `s`, `ms`, `us`, `ns`)
- Powers the `tusk note list --since` flag; compound forms (`1w2d`) are rejected for grammar clarity

### Breaking Changes

None for existing tusk CLI or MCP users. The new default policy blocks two fields on MCP project tools — but those tools are disabled by default anyway, so the effect is only visible to operators who had already opted them back in.

### Usage

```bash
# Create notes — body can be literal, from a file, or stdin
tusk note add "shipped the auth rewrite" meta.topic=auth --player german
tusk note add @./decisions.md meta.scope=architecture --player german
echo "quick thought" | tusk note add @- --player german

# Attach a note to a task
tusk note add "pairing notes" --task a3f8 --player german

# List — defaults to your own notes in the default project, trailing window applied
tusk note list --player german

# Scope and filter
tusk note list project=backend --player german
tusk note list project=backend --all-players --player german
tusk note list project=backend player=alice --player german
tusk note list --task a3f8 --player german
tusk note list --since 7d --player german
tusk note list --window 50 --archived --player german

# Archive (author-only)
tusk note archive 2f4a --player german

# Per-player window override
tusk player modify agent-1 note-window-size=50
tusk player modify agent-1 note-window-size=     # clear

# MCP field restrictions
# ~/.config/tusk/config.toml
[mcp.blocked_fields]
tusk_task_modify   = ["priority", "due"]
tusk_project_modify = ["workflow"]
tusk_project_delete = ["force"]
```

### Configuration

```toml
[notes]
window_size = 20

[mcp.blocked_fields]
tusk_project_modify = ["workflow"]
tusk_project_delete = ["force"]
```

The `[notes].window_size` default applies project-wide when no per-player or per-project override is set. The `[mcp.blocked_fields]` map enforces field-level write restrictions on enabled MCP tools; unknown tool names or fields fail `tusk mcp serve` at startup.

### Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Notes are append-only | Archive, never edit | Notebook semantics — what an agent thought at a point in time should not mutate |
| Window applied in SQL | `LIMIT N` in the generated query | Avoids materializing large histories in Go just to slice them |
| Per-project override on DB row | `ProjectSettings.NoteWindowSize` | Projects moved to DB in v0.10; config file no longer owns project metadata |
| Resolution fallthrough on error | Silent skip to next tier | Transient lookup failures degrade gracefully to project/global defaults |
| `meta.key=value` symmetric with `uda.key=value` | Prefix namespace on bare tokens | Consistent with the v0.11 inline-field principle |
| CLI accepts prefix, MCP requires full UUID | Asymmetric by design | Agents already have the UUID from list results; humans need shorthand |
| Hand-maintained tool-field registry | `toolFields` map | Reflection over MCP schemas is brittle; explicit registry is cheap and startup-checked |
| Startup validation against registry | Reject unknown tools and fields | Blocked-field drift should fail boot loudly, not silently allow writes |
| Dotted sub-keys rejected | `uda.env` fails startup | Field-path grammar deferred; flat field names only in v0.12 |
| Runtime guard at top of every handler | `s.checkBlocked(...)` before service calls | Defense in depth against config drift, reload races, and arg-shape bugs |
| Error message lists fields sorted | `[due, priority, title]` | Deterministic output for tests and for agents parsing the message |
| Default blocklist on project tools | `workflow` on modify, `force` on delete | The two fields an agent could use to reshape the workspace even with top-level disables lifted |
