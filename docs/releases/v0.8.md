# v0.8 — Programmatic Access

Expose tusk's core APIs as importable Go packages so other programs can embed tusk as a library.

### Highlights

**Package Restructure**
- Core packages moved from `internal/` to top-level: `domain`, `config`, `repository`, `filter`, `service`, `sqlite`, `inmem`
- CLI rendering (`internal/tui`) and MCP server (`internal/mcp`) remain internal
- All import paths updated — pure refactor, no behavioral changes

**High-level Client**
- `tusk.NewClient(tusk.Config{DBPath: "..."})` opens DB, runs migrations, wires all services
- `client.Close()` releases the database connection
- Services exposed as public fields: `Tasks`, `Tags`, `Relations`, `Projects`, `Workflows`, `Players`
- Zero-config defaults: builtin kanban workflow, default project, default urgency weights

**Building-block Packages**
- `domain` — core types (`Task`, `Project`, `Workflow`, `Player`, sentinel errors)
- `repository` — interface definitions for custom storage backends
- `service` — business logic (the primary API surface)
- `sqlite` — default SQLite storage implementation
- `inmem` — config-backed in-memory repos (projects, workflows)
- `filter` — filter expression parsing for programmatic queries
- `config` — configuration types (reused by Client)

### Usage

```go
client, err := tusk.NewClient(tusk.Config{
    DBPath: "/tmp/my-tasks.db",
})
defer client.Close()

task := &domain.Task{Title: "Build the thing"}
client.Tasks.Create(ctx, task)
```

### Config Behavior

| Field | Zero value | Behavior |
|-------|-----------|----------|
| `DBPath` | `""` | Error (required) |
| `Workflows` | `nil` | Builtin kanban workflow |
| `Projects` | `nil` | Builtin default project |
| `Urgency` | `UrgencyConfig{}` | Default weights |

No file loading, no environment variables — configuration is purely programmatic.

### Design Decisions

- **Reuse config types** — `tusk.Config` references `config.WorkflowConfig`, `config.ProjectConfig`, `config.UrgencyConfig` directly; no wrapper types
- **Private store** — consumers interact through services, not raw DB; `Close()` is the only lifecycle method
- **Always auto-migrate** — matches CLI behavior; consumers who want migration control use building-block packages directly
- **Hardcoded defaults** — Client bypasses Viper intentionally; defaults match `config/default.toml`
