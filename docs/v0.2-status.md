## Key Features in Detail

### Relation Service — Cycle Detection

`RelationService.Add` wraps relation creation in a transaction and runs DFS cycle detection for `blocks` edges before committing. Supported relation types: `blocks`, `relates_to`, `duplicates`. Duplicate relations return `ErrDuplicateRelation`; cycles return `ErrCyclicBlock`.

### Completion Propagation

When a child task transitions to a trigger status (default: `completed`), the parent is automatically transitioned to a target status (default: `completed`) if **all** children have reached the trigger. Propagation is recursive up the ancestor chain (bounded at 100 levels).

When a child moves **away** from the trigger status, the parent is auto-reverted (default: back to `active`).

Both behaviors are configurable per-project via settings:

```bash
tusk project modify myproject --set auto_complete_parent.trigger_status=completed
tusk project modify myproject --set auto_complete_parent.target_status=completed
tusk project modify myproject --set auto_revert_parent.trigger_status=completed
tusk project modify myproject --set auto_revert_parent.target_status=active
```

### Project Management

Projects now have a `version` field (optimistic locking) and a `settings` JSON column. `ProjectService.Modify` supports dot-path updates (`--set`/`--unset`) for nested settings, plus description updates.

### Tag Management

Full CRUD with safety guards:
- **Create** fails on duplicate name (`ErrConflict`)
- **Delete** fails if tag is assigned to any task (`ErrTagInUse`)
- **Rename** fails if new name already exists (`ErrConflict`)
- **Modify** updates tag color
- **ListWithUsage** returns each tag with its task count

## New Domain Types and Errors

### Error Sentinels (added in v0.2)

| Sentinel | When |
|----------|------|
| `ErrCyclicBlock` | DFS detects cycle in `blocks` relations |
| `ErrCyclicParent` | Parent assignment would create cycle |
| `ErrDuplicateRelation` | Relation already exists |
| `ErrTagInUse` | Deleting tag that is assigned to tasks |
| `ErrSourceNotFound` | Link source task not found |
| `ErrTargetNotFound` | Link target task not found |

### Types

| Type | Package | Purpose |
|------|---------|---------|
| `ProjectSettings` | `domain` | Holds AutoCompleteConfig + AutoRevertConfig pointers |

| `AutoRevertConfig` | `domain` | TriggerStatus, TargetStatus for parent auto-revert |
| `TagWithUsage` | `domain` | Tag + TaskCount for `tusk tag list --usage` |
| `TaskTxProvider` | `service` | Interface for atomic propagation transactions |

## Architecture Changes

The core layered architecture is unchanged. Notable additions:

- **Transaction support for propagation** — `TaskTxProvider` interface lets the service layer run multi-task status changes atomically. SQLite implements it with `BEGIN IMMEDIATE`.
- **Dot-path settings merge** — `ProjectService.Modify` accepts `--set key=val` / `--unset key` for nested JSON settings, avoiding full-object replacement.
- **Recursive propagation** — `checkAutoComplete` and `checkAutoRevert` walk up the parent chain within a single transaction.

### Known Limitations (carried from v0.1)

- **No quoted string support in filters** — `title:"my task"` and `description:` filters blocked until the lexer supports quoted strings
- **No boolean operators** — filters are AND-only; OR only within comma-separated values
- **No pagination** — `tusk list` returns all matching tasks
- **No sorting** — tasks returned in `created_at` order (urgency sorting is v0.4)
- **No config file loading** — `config/default.toml` exists as a template but isn't read at runtime
