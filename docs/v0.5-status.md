## What Was Built

v0.5 adds rich content capabilities: file-based description input and user-defined attributes (UDA). UDA exposes the existing `Task.UDA` field and `tasks.uda` JSON column through CLI flags, MCP parameters, text rendering, and filter syntax. The domain layer gained shared validation helpers, the service layer gained merge semantics for UDA updates, and the filter pipeline gained `uda.key:value` query support backed by SQLite `json_extract`.

### CLI Changes

No new commands. UDA is exposed through flags on existing commands:

```
tusk add "task" --uda env=prod --uda team=backend    # Set UDAs on creation
tusk modify <id> --uda env=staging                    # Merge UDA key
tusk modify <id> --uda env=                           # Remove UDA key
tusk info <id>                                        # Displays UDA section
tusk list uda.env:prod                                # Filter by UDA value
tusk list uda.env:                                    # Filter: key absent/empty
tusk list uda.env:prod uda.team:backend               # AND filter
```

### MCP Changes

No new tools. UDA added as parameters on existing tools:

- `tusk_task_create` — optional `uda` object parameter
- `tusk_task_modify` — optional `uda` object parameter (merge semantics)
- All task tool responses now include `uda` field (previously missing)

## Key Features in Detail

### File-Based Description Input

`--description @file.md` reads description content from a file on disk. Works on both `tusk add` and `tusk modify`. MCP tools already accepted full descriptions; no MCP change needed.

### UDA Domain Validation

Two exported validators in `internal/domain/task.go`:

- `ValidateUDAKey(key string) error` — regex `^[a-zA-Z_][a-zA-Z0-9_-]*$`. Rejects empty keys, keys starting with digits, and keys containing JSON path characters (`.`, `$`, `[`) to prevent `json_extract` injection.
- `ValidateUDA(uda map[string]any) error` — validates all keys and ensures all values are strings. Nil map is valid.

Both CLI and MCP call the same validators at the boundary.

### UDA Merge Semantics

`TaskService.Update` replaces whole-map replace with merge:

1. Validate incoming UDA via `domain.ValidateUDA`
2. Initialize target map if nil
3. For each key: empty string value → delete; non-empty → set/overwrite
4. Repository writes the full merged map

`TaskService.Create` validates UDA before persisting. Invalid keys or non-string values are rejected with descriptive errors.

### UDA Filter Pipeline

Three-stage extension of the existing filter system:

| Stage | File | Change |
|-------|------|--------|
| Parser | `internal/filter/parser.go` | `uda.*` prefix check before unknown-field error; validates key via `domain.ValidateUDAKey` |
| Resolver | `internal/filter/resolve.go` | Default case maps `uda.*` fields to `TaskFilter.UDA map[string]string` |
| SQL | `internal/sqlite/task.go` | `json_extract(uda, ?) = ?` for value match; `(json_extract(uda, ?) IS NULL OR json_extract(uda, ?) = '')` for absent/empty |

Multiple `uda.*` filters are AND'd. Keys are sorted for deterministic query generation. No index on `json_extract` — acceptable for expected data sizes.

### UDA Display

`tusk info` renders a UDA section after existing fields when `len(task.UDA) > 0`:

```
UDA:
  env:   prod
  team:  backend
```

Keys sorted alphabetically. Single-line values inline with aligned padding. Multi-line values indented below the key. JSON output already includes UDA via `taskJSON.UDA` — no change needed.

## Design Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Flag syntax | `--uda key=value` (repeatable) | Simple, avoids comma-in-value ambiguity |
| Value types | All strings | Avoids type coercion confusion; typed UDAs deferred to v0.9 |
| Modify semantics | Merge (not replace) | Prevents accidental data loss |
| Clear a key | `--uda key=` (empty value) | Mirrors `--description ""` and `due:` clear conventions |
| MCP parameter shape | `"uda": {"key": "value"}` object | Natural for agents, maps directly to domain type |
| Filter syntax | `uda.key:value` and `uda.key:` | Consistent with existing `key:value` filter convention |
| SQL implementation | `json_extract` without index | Acceptable for expected data sizes; indexing deferred |
| Wildcards/patterns | Deferred to v0.6 | YAGNI — simple equality covers current needs |

### Known Limitations (carried from v0.4)

- **No quoted string support in filters** — `title:"my task"` and `description:` filters blocked until the lexer supports quoted strings
- **No boolean operators** — filters are AND-only; OR only within comma-separated values
- **No pagination** — `tusk list` returns all matching tasks
- **No sorting** — tasks returned in `created_at` order (urgency sorting is v0.6)
- **UDA values are untyped** — all values stored as strings; typed UDA validation deferred to v0.9
- **No UDA filter in MCP list** — MCP `tusk_task_list` uses explicit parameters, not filter syntax; UDA filter is CLI-only
